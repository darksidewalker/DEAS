# DEAS desktop shell

Tauri 2 embeds the React production output from `../dist` in a native binary named `deas`. Rust owns the native provisioning orchestration directly; no Go installer sidecar is launched. Existing ComfyUI connections remain read-only. The native installer is a limited Linux/Windows x86_64 CPU/NVIDIA baseline (Windows runtime installation not yet accepted), not full Go-installer parity.

## Verify and build

From the repository root, build the frontend first with `npm run build`. Then:

```sh
export CARGO_TARGET_DIR="$HOME/.hermes/cache/scratch/deas-target"
cargo test --manifest-path src-tauri/Cargo.toml
cargo build --manifest-path src-tauri/Cargo.toml
```

The native executable is `$CARGO_TARGET_DIR/debug/deas`. A desktop session, WebKitGTK 4.1 and GStreamer `good` plugins (`gst-plugins-good`; WebKit aborts on media without `autoaudiosink`) are needed on Linux. Before GTK/WebKit initialization, the binary supplies process-local defaults `__NV_DISABLE_EXPLICIT_SYNC=1` (NVIDIA Wayland: keeps WebKit's GPU renderer from a protocol error) and `GDK_BACKEND=wayland,x11` (try Wayland, then X11). Launch the binary directly; no wrapper or exported variable is needed. Existing explicit overrides are preserved, including `WEBKIT_DISABLE_DMABUF_RENDERER=1` to fall back to CPU rendering or `GDK_BACKEND=x11`/`wayland` to force one backend. This does not force software OpenGL, change system settings or replace missing system libraries.

Tauri CLI development uses `http://localhost:1420` and `npm run dev`. Its build hook runs `npm run build` before embedding assets. Direct `cargo build` does not run that hook.

## Source-bound model family declarations

`invoke('native_model_family_write', {path, family})` explicitly writes a built-in family ID beside a model as `<file>.deas.json`; `family:null` resets it to automatic detection. The existing local-main `allow-download-plugins` permission grants this command; lib and desktop registration use the same command. Only checkpoint/diffusion-model/UNet and supported LoRA families from `src/families/builtin.json` are allowed. Companion folders cannot become runnable model declarations. A declaration is user-supplied compatibility information, not a successful load or verification of a model's architecture or format; GGUF uses supported split diffusion/video recipes and single/dual GGUF text-encoder loaders; self-contained GGUF checkpoints, GGUF VAEs and GGUF projection files are explicitly unsupported. All LoRA files remain Safetensors-only. Manual family assignment does not override the installed loader's architecture support.

Returned/scanned `LocalModel.family` is the effective family, `detectedFamily` is the unchanged header/provider detection, and optional `familyOverride` is the valid explicit declaration. `metadataError` blocks execution when metadata is invalid or a declaration belongs to a replaced/modified file, including the unknown-checkpoint fallback. An explicit write/reset can rebind a structurally valid stale sidecar to the current source, discarding stale provider/hash results; malformed/unsafe sidecars refuse and require external repair, never silent replacement.

Saving/resetting reads no weight payload and performs no hashing, CivitAI request, download or source-file edit. Declaration-only sidecars omit `sha256`, `fetchedAt` and `civitai`, retain a source fingerprint and size, and return `info:null` until explicitly enriched. Existing fetched sidecars retain their public `ModelInfo` shape; hashes/provider data are preserved when source-bound. Legacy sidecars keep their existing policy (parseable, but without trusted source identity their fetched result is not reused). Refresh merges an existing declaration and optimistically refuses a concurrent metadata write instead of overwriting it. The existing bounded, trusted-permission, no-follow/single-link cache reader, exclusive temporary, source recheck and `CACHE_PUBLICATION` atomic commit are reused. Write/reset failures emit redacted fixed-operation shared Logs entries without paths, family input or raw OS errors.

Focused checks: `cargo test --manifest-path src-tauri/Cargo.toml --locked --offline --lib downloads::models::tests` and `npx vitest run src/lib/models.test.tsx`. Fixtures cover sparse 8-GiB no-hash writes/reset/rescan, automatic detection, source replacement, invalid declarations/cache preservation, provider/hash retention, explicit enrichment, concurrent refresh refusal, shared logging and registration. These are filesystem/loopback tests, not real-model or Windows runtime evidence.

## Read-only IPC

```ts
invoke('inspect_backend', { baseUrl: 'http://127.0.0.1:8188' })
```

Returns `{ baseUrl, nodeCount, devices, missingRequiredNodes, capabilities }` with camelCase keys. Device names and node counts come only from backend responses. Required node IDs are `MiniMaxH3Director` and `MiniMaxH3DirectorGuide`. Capabilities are sorted feature keys, excluding null and explicitly false entries; no health status or inferred feature support is invented.

Only GET requests to `object_info`, `system_stats`, and `features` under the selected base path are sent. `features` 404 means no reported capabilities; other HTTP failures, invalid JSON, and malformed mandatory data return an error. A 3-second connect timeout, 10-second per-request total timeout, and 16 MiB streamed-response cap apply. Redirects and environment proxies are disabled. HTTP/HTTPS URLs only; credentials, queries, and fragments are rejected.

Local `main` window capabilities permit read-only inspection, scoped hardware/folder discovery, the read-only native installer-defaults command, the four native installer commands and the three explicit owned-backend commands. Remote-origin IPC, shell/filesystem plugins, and browser-to-backend network access are not granted. CSP restricts scripts and assets to the embedded app and permits only Tauri IPC connections.

## Read-only imported-video source inspection

`invoke('native_video_post_inspect', {title: 'Inspect video source'})` opens an explicit native rfd video chooser and returns `null` on cancellation. The local-main-only `allow-native-video-post-inspect` permission grants inspection and the metadata-only output-draft command below. No executable, source path, tool arguments, backend endpoint or model settings are accepted from the frontend. Titles are bounded to 240 bytes without controls; one native semaphore covers the chooser and owned probe, including a probe whose IPC waiter disappears. Concurrent requests refuse rather than queue more tools.

Success is camelCase `{sourceId?,name,width,height,fpsNumerator,fpsDenominator,durationSeconds,pixelFormat,fieldOrder,colorTransfer,audioStreams,subtitleStreams,blockers,timingVerified:false,processingReady:false}`. Only the file basename is returned. Rates are exact GCD-normalized rational numbers, not floating-point estimates; unavailable rates return `0/1` plus `cadenceUnknown`. Duration may be null. Matching nominal/average rates are only a metadata heuristic, **not proven CFR**. Neither readiness flag can become true, even with no blockers. A successful explicit chooser inspection now returns a fresh session-only UUIDv4 `sourceId` and privately retains exactly one source handle, verified identity and metadata. Cancellation/failure preserves the previous source and preparation; successful replacement invalidates the previous preparation even for the same basename. The native-only CLI inspection helper does not grant an ID. This command does not prepare an inference plan, load models, initialize a GPU or write output.

Rust directly invokes the installed `ffprobe` on PATH, without a shell or Python/Go worker. Install FFmpeg including ffprobe separately; missing tools return an actionable sanitized error and are never automatically installed. Metadata-only `-show_streams -show_format -of json -v error` uses a forced MP4/Matroska demuxer, file-only protocols, disabled MOV external data references, 4 MiB probe size, 1-second analyze duration, 64 MiB individual allocation cap, 1 MiB stdout, 16 KiB stderr and a 10-second wall deadline. No frame export or full-frame traversal is requested. Probe failures/nonempty error output fail closed; raw stderr and filenames are never logged. Linux owns an unreaped private process group; Windows uses the existing kill-on-close Job Object helper. Both terminate owned children before joining bounded readers.

Selection requires an absolute regular file of 12 bytes–64 GiB, MP4 `ftyp` or Matroska EBML signature and no symlink/reparse leaf (Windows UNC/device paths refuse); ordinary symlinked parent navigation is allowed. Nonblocking no-follow Unix opens avoid FIFO traps. Native-held file identity, size and modification metadata are rechecked against the open handle and selected path after probing. These are pre/post safety checks, not a sandbox against hostile same-user filesystem races. Exactly one video stream is required; multiple-video sources reject structurally (`VIDEO_STREAMS`), rather than choosing one silently. Dimensions must be integers 1–65536 and duration, when reported, finite, positive and at most seven days. Malformed metadata rejects; absent color/field/cadence/aspect metadata blocks conservatively.

Stable blocker codes: `cadenceUnknown`, `cadenceMismatch`, `interlaced`, `fieldOrderUnknown`, `rotation`, `alpha`, `hdr`, `colorUnknown`, `unsupportedPixelFormat`, `unsupportedDimensions`, `nonSquarePixels`, `pixelAspectUnknown`. The conservative metadata baseline is even 16–8192 dimensions, `yuv420p`, progressive, BT.709 primaries/transfer/matrix and square sample aspect ratio. Any display matrix blocks (including zero-angle mirroring/shear); malformed rotation rejects. Non-square known SAR blocks as `nonSquarePixels`; unavailable SAR is `pixelAspectUnknown`. HDR/alpha metadata may produce multiple blockers. These are inspection limits, not a supported processing/model claim.

Fixed `video-post` origin/severity/operation diagnostics with a fresh operation UUID reach shared Logs once per explicit invocation; cancellation is INFO, never an error. Source names, titles, paths, media metadata, credentials, raw OS errors and probe output are excluded. Focused verification: `cargo test --manifest-path src-tauri/Cargo.toml --locked --lib video_post::tests -- --nocapture` exercises the parser, logging/cancellation, admission, local-file traps, real owned-child timeout/output/stderr/nonzero fixtures and missing-tool errors without requiring FFmpeg. The separate installed-tool smoke is explicit: `cargo test --manifest-path src-tauri/Cargo.toml --locked --lib video_post::tests::real_ffmpeg_clip_inspected_by_production_native_helper -- --ignored --exact --nocapture`. It generates a tiny CFR SDR MP4 with FFmpeg/libx264 and inspects it through `video_post::inspect_source` (native-only helper, not IPC). Native chooser interaction and Windows runtime acceptance remain separate gates.

## TVE source retention and backend upload

`native_video_post_inspect_path({path})` is the Media-panel seam: an absolute path of a file DEAS already lists goes through the same admission, source checks and retention as the chooser. The inspected source is retained in native memory under a fresh UUIDv4 `sourceId`; `native_video_post_upload({baseUrl, sourceId})` rechecks it and copies it into the bound backend's input folder for a `video-enhance` intent, returning the backend input name. No other command accepts a path; the standalone Rust render engine was retired in 0.1.67 (`video_post_source.rs` replaces the prepare/draft/job/stream/upscale modules).

## Read-only execution API negotiation

`invoke('native_negotiate_api', {baseUrl})` requires an explicit HTTP/HTTPS endpoint and returns `{baseUrl, protocol: 'classic'|'v2', generationReady:false, capabilities}`. It never starts a service or submits a graph. Only `allow-native-negotiate-api` grants this command to the local main webview.

Probe the documented proxy `api/v2/health`, then protected `api/v2/jobs?limit=1`; only health 404 authorizes Classic `GET prompt` fallback and `exec_info.queue_remaining` validation. Health metadata's upstream URL is never followed. Successful v2 probes establish health/listing contracts, not functioning upstream computation or all execution operations. JSON response bodies are bounded at 64 KiB; five-second request and ten-second total deadlines apply. Redirects and environment proxies are disabled. Schema pinned to official proxy source commit `1569dc17ec0dd293d4b9a0723e142204dacedb85`.

Failures reject with `{code,endpoint,message}`: invalidEndpoint, authentication, redirect, html, malformed, incompatible, http, transport, timeout or responseTooLarge. Auth/HTML/schema failures never silently become Classic success. Nine native HTTP-fixture tests verify probe behavior, paths, errors and bounds; real ComfyUI/proxy execution remains unverified.

## Native Workbench Run admission

`invoke('native_workbench_run', {baseUrl, intent, confirmed:true, admissionEpoch})` prepares and submits one immutable per-press intent immediately, not a deferred native FIFO. `admissionEpoch` is required: capture it from the current collection before asynchronous preparation for that press. The initial epoch is `0`. The IPC boundary rejects missing, null, negative, fractional, string and other malformed epochs; values above JavaScript's maximum safe integer (`9007199254740991`) also refuse without preparation or submission. Run compares the expected epoch under the same root mutex used by Stop before reserving capacity; stale epochs refuse even after Stop completes and admission reopens. Never silently refresh/retry a rejected old Run: a new explicit press uses the new epoch.

The collection retains up to 20 entries; active/unknown jobs and unsent reservations are never evicted. Only positively terminal entries can make room. Independent runs retain their exact endpoint, intent/seed, consumed plan and captured output-root identity. The exclusive diagnostic slot remains mutually exclusive with active/unknown Workbench work. Run confirmation, validation, capacity or epoch refusal does not advance the epoch.

## Native Workbench polling

`invoke('native_workbench_current')` is an argument-free, network-free session snapshot. `invoke('native_workbench_poll')` refreshes the held Workbench jobs and returns the same `{jobs, preparing, capacity:20, stopAvailable:true, admissionEpoch, stopping}` envelope. Both use the existing local-main-only `allow-native-diagnostic-jobs` permission; neither polls the exclusive diagnostic slot or accepts frontend endpoints/job lists. Each job may carry `outputRoot` from its native-held `MediaRoot`; every snapshot revalidates the captured directory identity and omits the field if the directory is unavailable or replaced. Frontend output paths must use this per-job value, never current environment folders or endpoint equality; absent roots use job-bound transfer without fabricated local-path actions.

Polling reuses prompt/client/immutable-graph correlation and output handling, with up to 20 concurrent status operations, each bounded by the existing 15-second status deadline (3-second connect / 10-second request limits, 1 MiB responses). Terminal/submitting jobs are skipped; missing prompt IDs remain unknown without requests. Per-job transport failures become unknown without blocking peers or evicting uncertain jobs. Overlapping aggregate polls return the current snapshot immediately, never queue another pass. An admitted pass finishes even if its IPC waiter disappears, so per-job polling flags are cleared. Polling only reads history/queue: no POST, submission retry, cancellation or automatic Run. Status/error changes use the existing sanitized shared Logs path. Studio now uses native Run, session recovery and collection polling; the diagnostic prepare/submit/status path remains separate. Repeated Run admission is native-bounded; Stop fences delayed older presses as described below. Loopback/browser IPC fixtures are not real-model or Linux/Windows webview acceptance.

## Native preview-observer lifetime

Preview observation is private native state, absent from IPC snapshots and persisted history. Each admitted job's shared `Arc<Mutex<Live>>` owns one controller; temporary `Job` clones share it. The optional WebSocket task retains only a weak live-state reference, cancellation receiver and independent completion acknowledgement. It cannot keep the job/session/controller alive. Final native release wakes cleanup; abandoning an IPC waiter or remounting React does not cancel still-owned observation.

Terminal submission rejection, successful/failed/cancelled status commits and scoped-cancellation terminal proof signal cleanup. Confirmed aggregate Stop signals each held observer at invalidation, including partial/unknown outcomes, without adding backend mutations or inventing terminal state. Ordinary transient unknown status keeps observation and reconciliation intact. Diagnostic replacement and terminal eviction release ownership without changing cached outputs or history.

Cancellation wakes the existing three-second connection, 600-second idle receive and bounded Pong/peer-Close flush waits. Cleanup retains a graceful one-second Close handshake even if the peer refuses its reply; no socket I/O is awaited under session/live mutexes. Frame publication rechecks cancellation under the same live lock. Existing client/prompt filtering, preview magic/size limits and plain-WS best-effort transport remain unchanged; no reconnect/TLS/public command is added. Transport failures use fixed redacted shared warnings, canonical client identity where available and per-operation rate limiting. Observer closure is display cleanup, never `/interrupt`, queue deletion, service Stop or execution proof.

Portable loopback fixtures count actual cleanup completion and retain queue/history/output assertions. They are authored but unexecuted until Cargo is available; native platform/resource acceptance remains pending. See [verification](../docs/VERIFICATION.md#h-02a-owned-preview-observer-lifetime-0155).

## Recent generation history

`invoke('native_jobs_history', {})` reads the optional app-local history without contacting an endpoint, inspecting stored output paths or creating live jobs. The local-main-only `allow-native-jobs-history` permission grants this read, a fixed diagnostic command and the explicit bounded availability check below; saved IDs, endpoint origins and paths do not authorize cancellation, submission, uploads or output retrieval.

The response is `{schemaVersion:1, records, readOnly, error}`; records are newest-admission first and capped at ten globally. Each strict record contains native job/client/prompt identity, Studio/diagnostic origin, app version, admission/observation times, monotonic record revision, known backend start/duration, last-observed state, validated effective image/video intent, current output descriptors and optional captured output root/identity. Unknown timing stays null. Backend origins omit credentials and path/query data; stored error summaries are fixed and bounded. Intent validation reuses the existing native compiler whitelist, preserving both image-reference schemas, optional image operations and video settings. Graphs, live previews, PNG arrays, interrupt tokens and admission/ownership epochs are excluded.

The store is `recent-generation-history.json` under Tauri app data, with schema version 1 and an OS-held writer lock. Validated bounded reads preserve corrupt, unknown-schema and competing-writer data; failures yield degraded/read-only history and rate-limited redacted shared Logs. A one-slot notification channel coalesces meaningful owned native commits; serialization and atomic publication run on a dedicated worker outside job locks. Unchanged polls and progress frames do not write. Exclusive owned temporaries, identity checks, file sync and existing anchored Linux/Windows atomic publication preserve the previous file on pre-publication failure; post-publication durability uncertainty is reported honestly. No temporary owned by another writer is removed. Normal application Exit waits at most two seconds for the latest history revision; an incomplete flush reports degraded persistence. Forced termination/power loss may lose unsaved observations.

Records are limited to 16 MiB each and the whole file to `10 * 16 MiB + 4096` bytes. Ordinary image/video/reference fixtures are much smaller. The upper bound accommodates the existing wildcard contract: 4096 selection keys of up to 512 UTF-16 units can require about 12 MiB when JSON escapes control characters, plus bounded prompts, reference names and options. Effective settings are never truncated; exceeding a bound degrades optional history without changing generation. This is a storage bound, not measured large-history UI/resource acceptance.

Admission occurs after native plan consumption/job assignment and before network awaits. Native owned submission/status/cancellation tasks update records even after IPC waiter loss. Updates merge only existing identities, retain original admission order and cannot resurrect pruned jobs. The twenty-entry native collection is independent. Persisted nonterminal rows remain last-observed historical state after restart; no recovery/probe/retry occurs. Pruning removes metadata only.

`invoke('native_jobs_history_outputs', {jobId})` is an explicit local-only check. Native code resolves the currently approved environment's output root, requires both its path and filesystem identity to match the saved record, and returns one `available|missing|unvalidated` value per output. No caller root/path/endpoint is accepted. Unsafe links, refused access or unverified context remain unvalidated/refused rather than being labelled missing. Stored paths alone never grant access. `native_logs_history_error` accepts only optional `read|outputs` operation codes and emits fixed rate-limited shared diagnostics, never arbitrary frontend text.

Successful authorized Star/Unstar moves repair matching current output locations, including restart-loaded rows; executed intent remains unchanged. History persistence failure after a move is a separate degraded-history outcome and does not repeat, undo or deny the physical move. Studio restores settings only through an explicit review/apply mapper and keeps unsupported or missing authoring dependencies visible. Schema 1 has no original input-context binding: sources/references/frames remain unresolved until explicit Media selection, regardless of filename/origin/output-root matches. Output availability presentation is scoped to the selected context, record revision and open lifecycle; invalidated replies cannot relabel a different selection. Native output-root authority and the ID-only command are unchanged. A scratch-only successful worker initialize/admit/observe/flush/reopen regression is authored; it has not run without Cargo. See [Studio history](../docs/STUDIO.md#recent-generation-history); native platform acceptance remains separately required.

## Native Workbench pending cancellation

`invoke('native_workbench_cancel_pending', {jobId, confirmed:true})` uses the local-main `allow-native-diagnostic-jobs` permission and returns the normal native job snapshot. Only a held Workbench job ID is accepted; there are no endpoint, prompt-ID, graph, token or diagnostic-slot inputs. Confirmation, busy and ownership refusals reject with a sanitized string. Missing prompt IDs stay unknown without requests. Unknown/running jobs can reconcile read-only; this call does not delete them.

For a queued job, native code requires the exact currently owned running HTTP IPv4 loopback listener, correlates its stored prompt/client/immutable graph against history/queue, and rechecks the owned lifecycle before sending exactly `POST /queue {delete:[heldPromptId]}`. Core ComfyUI's empty HTTP 200 reply is required, with a streamed 1 MiB cap; non-empty 200 acknowledgements (including HTML/JSON) are rejected rather than treated as deletion success. The existing client disables redirects, retries, environment proxies and credentials (3-second connect / 10-second request bounds); the complete operation has a 40-second deadline. Remote/proxy/authenticated endpoints are unsupported, including 401/403; no provider token is forwarded.

Same-lifecycle readback preserves running/completed transitions and successful outputs; absence receives a second history/queue read to close a completion-between-reads window. Only accepted deletion plus absent readback becomes terminal `cancelled`. Lost/rejected/oversized replies, failed correlation/readback or a lifecycle change remain `unknown`, not presumed cancelled. Once a delete is attempted, snapshots include `pendingCancellationAttempted:true`; that session-held marker survives read-only reconciliation and blocks every further delete for the job. Polling/submission and cancellation share the per-job busy guard, and admitted cancellation finishes even if its IPC waiter disappears. Sanitized shared Logs distinguish pending cancellation; refusals/uncertainty are rate-limited. This is a bounded Classic core adapter, not an atomic backend cancellation protocol or hostile same-user socket-replacement defense.

No queue clear or resubmission is permitted. Native whole-queue coordination is documented below; `stopAvailable:true` advertises that coordinator, not universal per-job cancellation support. Real loopback HTTP fixtures cover these contracts; real ComfyUI/model execution and Windows runtime cancellation remain unverified.

## Native Workbench running interruption

`invoke('native_workbench_interrupt_running', {jobId, confirmed:true})` uses the same local-main permission and normal job snapshot as pending cancellation. The only inputs are a held Workbench job ID and explicit confirmation. Diagnostic jobs, foreign endpoints and caller-supplied graphs/prompt IDs/tokens cannot authorize it. Missing prompt IDs stay unchanged; submitting/polling or previously attempted jobs refuse. Unknown jobs reconcile read-only, pending jobs are not deleted, and completed jobs retain their products. The standalone status waiter now has a lock-disarmed RAII polling guard, so aborting it cannot strand cancellation or clear a later operation's flag.

**Core `/interrupt` is never used.** The inspected handler checks running IDs and sets its global processing flag in separate critical sections: even its targeted body can interrupt a foreign successor. Instead the existing owned-launch custom-node installation hook installs `deas_running_interrupt.py`. Its separate `POST /deas/jobs/interrupt` route holds `PromptQueue.mutex` across exact prompt/client/graph comparison and the flag set, requires a single current matching running tuple, and returns empty HTTP 200 only when signalled (409 otherwise). The inspected executor resets the flag before executing the successor. It does not monkeypatch core or modify a foreign checkout.

Support is fail-closed and limited to inspected ComfyUI revision `b1a247c9cf9dbfda4b2c0a0c1d50950667eeaa0c`: native launch captures bounded validated `server.py`, `execution.py`, `main.py` and `nodes.py` against the SHA-256 pins in `backend.rs`, plus the installed adapter hash. `server.py`'s pin is `6e3614c753c95b037e57e25dfc2de979de70136baad2a3abb5d2d32aaf05281e`. LF and CRLF checkouts are accepted through the known normalized hashes; retained raw hashes must still match before each interruption. Unknown/missing/changed sources disable this optional capability without failing backend startup. A post-launch disk check cannot acquire capability absent at launch. Arbitrary custom nodes remain trusted backend code, not a sandboxed threat model.

A fresh native-held random token is passed only to that owned child through `DEAS_RUNNING_INTERRUPT_TOKEN`, removed from its environment by the adapter at import, and sent only in the sensitive `X-DEAS-Interrupt-Token` header. It is never an IPC result, preference or log entry; provider credentials are not used. The adapter rejects browser Origin calls and missing/wrong authority. Native code additionally reuses exact owned running loopback listener/lifecycle checks before and after requests. No adoption, legacy fallback, proxy, redirect, retry or process Stop is allowed. Transport bounds remain 3-second connect / 10-second request / 40-second operation and 1 MiB streamed replies; only empty HTTP 200 acknowledges the mutation.

Before the one possible POST, native snapshots record `interruptCancellationAttempted:true` independently of `pendingCancellationAttempted`; it survives reconciliation and prevents a second ambiguous interruption. Same-lifecycle history/queue readback, including a second absent read, determines the result. An acknowledgement alone is not cancellation: only correlated terminal `execution_interrupted` history yields `cancelled`; observed running stays `running`, successful completion retains products, and disappearance without terminal proof is `unknown`. Invalid/lost replies remain diagnostic uncertainty, never permission to retry. Shared bounded/redacted Logs distinguish running interruption. Admitted operations finish if their IPC waiter disappears.

Offline verification includes real loopback protocol fixtures, standalone waiter-abort regression, and a compact Python auth/mutex race fixture. The optional source-backed CPU fixture copies only explicitly selected read-only source into scratch, launches a fixture interpreter (never imports/executes the pinned model main), exercises the actual pinned `PromptQueue` class and executor reset statement, and validates launch/source/adapter/foreign/stopped checks for LF and CRLF:

```sh
DEAS_TEST_COMFY_SOURCE=/path/to/inspected/ComfyUI cargo test --locked --lib running_interrupt_source_backed_launch_proof_and_queue_race -- --ignored --nocapture
```

No real model/GPU, live user service or Windows runtime acceptance is implied. `stopAvailable:true` does not claim that interruption is supported for every held job or backend.

## Native whole-Workbench Stop

`invoke('native_workbench_stop', {confirmed:true})` is a local-main-only `allow-native-diagnostic-jobs` command. It takes no endpoint, graph, job list, prompt ID or credentials. It returns the existing `{jobs, preparing, capacity:20, stopAvailable:true, admissionEpoch, stopping}` snapshot plus `{outcome, discarded, issues:[{jobId,error}]}`:

- `empty`: no held jobs or unsent preparations existed.
- `settled`: all retained jobs are terminal (succeeded/failed/cancelled), or only unsent preparations were discarded. It does **not** mean every job was cancelled or that this invocation changed anything. Repeated Stop preserves terminal jobs/products and sends no further mutations.
- `partial`: at least one job is still running/queued/unknown, or a per-target refusal occurred. Inspect each job's true state/error/attempt markers and `issues`; an empty issues list does not imply completion. Ownership/unsupported interruption failures can leave a queued/running state unchanged. An accepted running signal remains partial until terminal history proves completion/interruption.

Missing confirmation rejects without admission changes or backend mutation. Each admitted confirmed Stop advances `admissionEpoch` exactly once under the admission mutex **before** invalidating any held plans, including an empty Stop. Overlapping Stops coalesce into that one advance/result; a later separate Stop advances again. The epoch persists after completion and after all IPC waiters disappear. It never wraps: advancing beyond `9007199254740991` refuses before any generation, plan, job or backend mutation. Current/poll snapshots report `stopping:true` while the coordinator runs; the final Stop result reports `stopping:false` with the updated epoch and retains `outcome`/`discarded`/`issues`. `stopAvailable:true` means the coordinator is supported, not that foreign jobs, unsupported source revisions or unknown targets are cancellable; those preserve the partial outcomes below.

Stop atomically closes Workbench admission, invalidates/drops unsent preparations and prepared snapshots, and pins each submitted target's owned lifecycle. Preparation GETs already in flight may finish, but cannot publish or submit their discarded plans. Submission installation and invalidation share the native-held lock: a submission that already crossed that boundary is allowed to settle exactly once, never resubmitted. Admitted Workbench Run now owns its prepare/submit task even if its IPC waiter disappears. Lost/malformed submission replies retain unknown jobs without inventing prompt IDs or scanning/adopting backend jobs.

For retained jobs Stop waits for admitted submission/status/cancellation work (45-second busy bound), suppresses new per-job polls and separate cancellations until it finishes, then uses correlated status (15-second bound) and the existing targeted pending-delete/scoped-running-interrupt implementations (40-second bound per path). Up to 20 targets proceed concurrently; one unsupported/unreachable target does not skip eligible peers. The lifecycle pinned at Stop admission is checked across both mutation paths. Pending→running races before or after deletion use the separate interruption path only after fresh correlation, with independent per-operation attempt markers. There is never a core `/interrupt`, global queue clear, service stop, retry of an ambiguous mutation, or diagnostic-slot cancellation.

An initially unknown settled submission with a known prompt ID is read-only reconciliation for that invocation; a later explicit Stop may act on its newly known queued/running state. Missing prompt IDs remain unknown without backend requests. Existing terminal products, output cache/completed reference records, and partial output metadata survive Stop uncertainty. Overlapping confirmed Stops share the admitted task/result; loss of any/all IPC waiters does not abort remaining targets or strand the admission gate. Completion reopens admission; it does not promise that an asynchronous running interruption has already taken effect.

Sanitized shared Logs identify Stop and native job IDs, never endpoints, prompts, backend error bodies or interruption tokens; existing cancellation refusal/uncertainty limiting applies. Loopback regression coverage includes admission/preparation/submission/poll/Stop races, lost Run/Stop waiters and replies, missing IDs, foreign correlation, targeted mutation counts, pending→running phases/lifecycle changes, partial peer failures, repeated/empty/unreachable Stop, and terminal cache/reference retention. This is native fixture evidence only. `stopAvailable:true` denotes coordinator availability only; real-model/GPU and Linux/Windows native-webview acceptance are not implied.

## Imported H3 video preparation

`invoke('native_h3_video_upload', {baseUrl})` (local-main `allow-native-diagnostic-jobs`) opens the platform video chooser (MP4/MOV/WebM/MKV) and returns a fresh backend-relative input filename or `null` on cancellation. It reuses the reference upload transport, requires video magic bytes and a regular file ≤ 512 MiB, preserves the local original, and never prepares/selects/runs a source. The UI only fills its filename draft; Prepare and Use remain explicit. Native upload failures reach shared Logs as fixed, path/URL/body-free, rate-limited diagnostics, including the existing `native_input_upload` callers. Native chooser and Windows runtime interaction remain separate acceptance gates.


`invoke('native_h3_video_prepare', {baseUrl, filename})` uses the existing local-main `allow-native-diagnostic-jobs` permission (already granted by `capabilities/main.json`). It sends exactly `POST <base-path>/df_h3_continuity/video` with `{filename}`. The name must already exist relative to the backend input directory: nonempty, at most 4096 UTF-8 bytes, forward-slash segments only; spaces/Unicode are preserved. Absolute/drive/backslash paths, empty/dot/traversal segments, controls/NUL and `[output]`/`[temp]` suffixes are rejected before network access. This command neither reads host media nor uploads it.

Success returns only `{sourceId, filename, sha256, width, height, fps, seconds, hasAudio}`. The echoed filename must match exactly, kind must be `video`, source/digest IDs must be 64 lowercase hexadecimal characters, dimensions must be integer 1–65536, duration/rate finite and positive, and audio a boolean. No frame count is invented. IDs are opaque: DEAS does not recreate source or VAE-cache hashes. HTTP/HTTPS base-URL validation, no redirects/proxies/retries, a 3-second connect timeout, 180-second total request timeout and 1 MiB streamed response cap apply; the bounded filename also bounds the JSON request. Failures reach shared Logs through a fifth fixed cause slot (first cause and first recurrence immediately, later repeats rate-limited to a minute), without filenames, URLs, response bodies or credentials.

`native_h3_session` retains its old clip shapes unless valid root-level `provenance.kind == "imported_video"` metadata is present. Such entries additionally expose `importedVideo: {sourceId, width, height, modeFamily}` from `provenance.source_video_id`, root dimensions and `mode_family` (`fl2va`/`ref2va`). This maps the opaque prepared source to the **backend-returned** VAE-cached checkpoint `clipId`; an extension's `parent` identifies that checkpoint, not the source manifest ID. Malformed or absent imported metadata is omitted, not guessed. No provenance filename, raw metadata or host path is added.

Contract inspected read-only at DaSiWa nodepack revision `1da4fefa` (`video_source.prepare_video`, `pyav_media.probe`, `ClipStore.metadata/list_clips`). The local checkout was already newer (`fcd0ec54623c`); no dependency was modified. HTTP-fixture tests cover sanitized exact POSTs, invalid-input no-network rejection, tampering/nonfinite fields, status/redirect/response bounds, safe rate-limited Logs and old/new session shapes. Real backend hash/probe, VAE import/inference and Linux/Windows webview acceptance are not established by these fixtures.

`ProjectSnapshot` returns `{id,root,revision,draft,input}`; disk `project.json` schema 1 omits the absolute root and stores the managed PNG reference relatively. ## Spellcheck dictionary IPC

It returns `{path, license, loaded}`; `loaded:false` means Enchant needs an app restart. No admin rights, no system package manager, no credentials; nothing downloads by merely opening Settings or typing.

`native_forge({baseUrl,root,route:"people",body:{model,path,request_id}})` reuses the existing local-main Forge permission. ## Automatic recommendations (read-only)

`invoke('native_install_defaults', {})` returns `{storagePath, backend, hardware, warnings}`. The default target is a new `deas-environment` in the running executable’s parent directory, independent of the shell working directory. Existing targets are reported, not adopted, renamed or changed. Supported NVIDIA hardware/driver profiles recommend `nvidia`; failed or incompatible discovery recommends `cpu` with an explanation, not a claim of detected CPU/AMD/Intel hardware. No files, plans, downloads or services are changed by this command.

Defaults are editable recommendations, not authorization. The final Start install action must use the exact current immutable plan and explicit native confirmation. Basic defaults do not implement the roadmap’s later capability/benchmark/launch-optimization mode.

## Native provisioning IPC

```ts
const plan = await invoke('native_install_plan', { request: {
  storagePath: '/absolute/existing-parent/new-deas-environment',
  backend: 'cpu',
  features: ['installer'],
  options: { sage: false, radial: false, flash: false, ffmpeg: false },
  comfyRef: 'master',
} });
await invoke('native_install_start', { planId: plan.id, confirmed: true });
const status = await invoke('native_install_status');
await invoke('native_install_cancel');
```

- Plan returns `{id, request, steps: [{id,labelKey,detail}], warnings, unsupportedOptions, canExecute, hardware, torch}`. Planning performs local reads and, for NVIDIA, a read-only argv-based `nvidia-smi` query (5-second timeout, 16 KiB output limit); it never creates target directories or downloads. Plans are immutable in app memory, capped at 64, and consumed once. IDs do not survive app restart.
- Start accepts only a stored plan ID and explicit boolean confirmation; the caller cannot replace the planned request. It returns status immediately and starts an owned asynchronous worker. Only one native installation runs at a time.
- Status returns `{state, stepId, logs, error}`, with state `idle|running|succeeded|failed|cancelled`. The last 300 log chunks are retained (4096 characters each). Cancel requests cancellation; poll until terminal state. It affects only this worker's downloads and newly created subprocess groups, never an existing ComfyUI server.
- For a fresh installation, `storagePath` is the **new environment directory**, not an existing model/project directory. Its parent must already exist. Roots, relative paths, traversal, symlink components and existing non-DEAS targets (even empty) are rejected. Start revalidates and claims a new directory exclusively. A completed DEAS target instead produces a checked reopen preview with `reopenId`; consume it through `native_install_open({planId: plan.id, confirmed: true})`, never `native_install_start`. The exact one-time native snapshot is revalidated before approval; opening does not reinstall, update, wipe or start a backend. Persisted and selected paths are compared by canonical identity without rewriting the saved plan. Partial failed/cancelled installs remain for inspection; no automatic deletion, wipe, resume, migration or rollback is offered.
- Supported backends are `cpu` and `nvidia` on Linux and Windows x86_64 (Windows runtime installation is not yet accepted). AMD/Intel and other OS/architectures are explicit blocked plans. NVIDIA requires one visible GPU; missing/failed probes, unsupported GPU families and insufficient drivers block execution with `NVIDIA_GPU`/`NVIDIA_DRIVER` messages. No fallback silently selects CPU. `sage`, `radial`, `flash` and `ffmpeg` selections block execution rather than being silently skipped. Git must be installed beforehand; no system package installer is run.
- Accepted features are `installer`, `director`, `forge`, `refmods`, `continuity`. Director selects its included Forge/RefMods/Continuity package: planning expands missing companion IDs in the immutable returned request before separate install consent. Already complete requests retain their exact order; unknown IDs are still blocked. Output is an included studio capability, not a separate native feature ID. Empty features also select only the baseline. Any of the four selected DaSiWa feature IDs fetch the DaSiWa nodepack once, from its `main` branch, and install its requirements; unknown features block execution. This does **not** install model weights, recipes or workflows or prove those features ready.
- `comfyRef` accepts a branch, tag or commit (for example `master`); URLs/options are rejected. Branch/tag revisions are resolved at execution and exact Git commits are recorded. No fallback silently replaces a requested reference.

The worker downloads official uv **0.8.22** for Linux x86_64 or Windows x86_64 MSVC, verifies an embedded release SHA-256, and extracts only the uv executable to `runtime/uv`. uv installs managed Python **3.12** under `runtime/python`, with local caches/config/home/temp directories and no user/system Python or PATH modifications. The venv is created at its final `venv` path. CPU retains the deliberate **Torch 2.8.0 / torchvision 0.23.0 / torchaudio 2.8.0** official CPU-index baseline (Go CPU is unpinned). NVIDIA ports Go config global/minimum 13.2 → effective **CUDA 13.0**, **Torch 2.14.1 / torchvision 0.29.1 / torchaudio 2.11.0**, official `cu130` index; Linux driver >=580 and capability >=7.5 are required. GTX 10/Pascal capability 6.0/6.1 instead selects **2.4.1 / 0.19.1 / 2.4.1**, `cu121`, driver >=525.60.13. Volta/older unsupported hardware blocks rather than receiving CUDA 13. No standalone developer toolkit or attention-extension build is provisioned; Torch wheel runtime dependencies are installed. Exact pins/index/hardware are stored in the immutable plan and reused by execution, not reselected; driver/UUID/capability changes fail before target creation. ComfyUI and node requirements receive wheel-family-qualified constraints and the selected extra index, with a percent-encoded `UV_CONSTRAINT` URI propagated to children. Commands use argv, not a shell; inherited Python/uv/pip/Git configuration is removed. Upstream dependency build code is trusted, not sandboxed.

Final checks import the exact Torch trio and verify either CPU tensor arithmetic or exact CUDA metadata, planned GPU architecture/identity and synchronized CUDA matrix multiplication. NVIDIA probes address the planned UUID. ComfyUI help uses `main.py --cuda-device 0 --help` for NVIDIA, `main.py --cpu --help` for CPU. `deas-plan.json` records the approved plan and `deas-install.json` records revisions and verification identities with `generationReady: false`. Success means these provisioning checks passed; no backend launch, API/node discovery or generation acceptance has occurred. GPU runtime acceptance is a required execution-time check, not something established by planning or the packaging tests below.

## Explicit owned-backend IPC

```ts
// All three commands have no caller-supplied arguments.
const started = await invoke('native_backend_start');
const status = await invoke('native_backend_status');
const stopped = await invoke('native_backend_stop');
```

Start resolves to the same status schema as status/stop, or rejects with a string for authorization/validation/duplicate-start/spawn failures:

```ts
type NativeBackendStatus = {
  state: 'starting' | 'running' | 'failed' | 'stopped';
  endpoint: string | null;
  logs: string[];
  error: string | null;
  generationReady: false;
};
```

`allow-native-backend` grants exactly these three commands to the local main webview. There are no executable, target, PID, port, URL, shell-command or arbitrary-argument IPC inputs. Installation planning and its separate explicit confirmation are unchanged. Provisioning itself does not launch a backend. Successful provisioning or checked `native_install_open` records current Engine approval with directory/file identities, exact plan/install manifests and launch-file hashes. A prepared plan, saved draft, failed/cancelled job or unvalidated existing folder cannot authorize start. An active owned backend must be stopped explicitly before changing environments. The frontend revalidates the last selected completed environment after restart and auto-starts its owned backend by default; Settings persists the opt-out. Check native status before one automatic start attempt, do not restart after manual Stop, and hold the OS environment lock until owned-process cleanup. Repair and recursive package attestation remain unimplemented.

Before each launch, native code rejects missing/replaced paths, symlink components in the guarded root/launch/manifest paths, changed manifests or launch files, foreign ownership and group/world-writable guarded entries. uv's venv interpreter link is materialized as a regular executable copy from the approved managed runtime during provisioning, before existing framework verification. The explicit uv/Python scratch smoke verifies that this copy preserves the real Python 3.12 venv/base-prefix and package import. These guards are not a sandbox for upstream package/node code and do not recursively attest every Python dependency/source file; concurrent hostile same-user filesystem mutation is outside this slice's threat model.

The child executes the managed venv interpreter (`venv/bin/python` on Linux, `venv/Scripts/python.exe` on Windows) with `-u main.py --listen 127.0.0.1 --port <one ephemeral port> --disable-auto-launch --enable-cors-header tauri://localhost` (CORS mode replaces ComfyUI's origin middleware, which otherwise answers the Comfy tab's cross-site iframe with 403), with `--cpu` or the approved NVIDIA `--cuda-device 0` (plus planned GPU UUID environment and bounded driver/device recheck). Its working directory is the owned `ComfyUI`; inherited Python/user configuration is cleared and home/cache/config/temp paths remain inside the owned environment. No SDK/proxy, models, cloud fallback or generation recipe is installed or submitted.

Startup reserves one loopback ephemeral port, releases it immediately before the one spawn and never retries another port or adopts a listener. **Ownership proof** correlates the exact unreaped child PID's `/proc/<pid>/fd` socket inode with the unique IPv4 `127.0.0.1:<chosen-port>` LISTEN record in `/proc/net/tcp`; `/proc/<pid>/net` alone is not used as proof. Ownership is required before and after bounded GET-only `object_info` and `system_stats` probes, and continued child/listener ownership is monitored while running. A foreign listener collision fails and only the newly owned child is terminated. Valid JSON and the existing inspector's mandatory node/device structure are required. API response status is not inferred from process liveness or log text.

The startup deadline is **120 seconds**, with a 500 ms connect timeout, 2-second request timeout, overall remaining-deadline enforcement and 16 MiB streamed cap per response. Status starts as `starting`, and exposes an endpoint only after owned API verification (`running`). Exit, ownership loss, invalid/stalled responses or deadline failure yield `failed` with retained bounded logs/error. Logs retain the latest 300 chunks, each at most 4096 characters. All states retain `generationReady:false`; API acceptance says nothing about models, required pack nodes, GPU generation or readiness to submit a recipe.

Stop is idempotent and accepts no PID. It kills only the freshly created private child process group and reaps its leader; it never looks up or terminates a service by port/name. Linux `waitid(WNOWAIT)` keeps an exited leader unreaped until private-group cleanup, avoiding PID/group-number reuse between observation and cleanup. Request serials prevent a stale startup probe from publishing running after stop/restart. Tauri exit events and lifecycle drop both clean up the owned child. The description above is the Linux path; Windows uses its own Job Object cleanup in code, but Windows runtime lifecycle is not yet accepted, and neither establishes survival cleanup after SIGKILL/power loss.

Default lifecycle tests use real scratch venv/Python children and local HTTP fixtures: successful API start/status/stop, duplicate start, timeout, stalled/invalid API, startup failure/logs, manifest/symlink/file tampering, ownership collision, listener loss, stop during probe, lifecycle drop and owned-descendant cleanup with an unrelated child left alive. The ignored uv smoke additionally exercises real checksum-verified uv and managed Python 3.12 through the Engine's **test-only fixture authorization**, real local HTTP readiness and shutdown. It is not a successful full ComfyUI/Torch provision or GPU execution test.
