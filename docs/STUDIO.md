## Music (YuE2) — 0.1.66

Generate offers **Music (Text to Music)** and **Music (Cover Music)** for YuE2 checkpoints (detected by header keys, listed like other checkpoints). Music replaces the positive/negative prompt pair with two independent editors: **Style** (required) and **Lyrics** (section tags like `[verse]`/`[chorus]` supported), each with the YuE2-specific writer from Prompt Forge, expand/copy/clear tools and its own draft — image prompts are never relabelled into music fields.

- **Text to music** chooses ABC planning **Off / Full / Melody**: Full/Melody generate an ABC sheet first (with their own ABC settings: max tokens, temperature, top-p/top-k, repetition penalty and window); Off skips straight to autoregressive generation with the AR settings (temperature, top-p/top-k, repetition penalty, AR CFG). Maximum duration bounds the requested length; the actual generated duration can be shorter. Seed, steps, CFG, sampler and scheduler work as in image generation.
- **Cover** takes an explicitly selected audio file or a video with audio: core `LoadAudio` reads its first audio stream, SheetSage2 transcribes it to a melody ABC, and YuE2 generates a **new** song from that melody plus Style/Lyrics. A cover always needs the selected **audio encoder** offered by the running backend; the source list is explicit and a silent/no-audio source blocks Run with a named reason. A cover is a melody reinterpretation — it does not preserve timbre, singer identity, accompaniment, exact tempo or duration, and there is no lyric transcription or voice cloning.
- Outputs are **FLAC**, retained in Recent generation history with full settings restore (the cover source must be re-selected explicitly). The Run Plan and Generation Metadata show the exact music intent. Missing YuE2/SheetSage2 nodes or writers disable only the dependent modes with a visible reason; nothing downloads automatically.

**Not yet accepted:** real YuE2 model generation quality, SheetSage2 list/multiplicity behavior on live backends, FLAC playback on the native WebKitGTK/WebView2 runtimes and external-backend export fallback, Windows runtime, and the inspected checkpoint's CC-BY-NC-4.0 source terms for any future download catalog. Full usage, graph shapes, tested revisions and the license notice: [MUSIC.md](MUSIC.md). See also [VERIFICATION.md](VERIFICATION.md#yue2-music-generation-and-covers-0166) and [open work](PLAN.md#43-music-yue2).

## GGUF models and manual architecture assignment

Use GGUF diffusion weights in `models/diffusion_models` or `models/unet`, and supported GGUF text encoders in `models/text_encoders` or `models/clip`. Select the matching separate VAE and, for LTX, audio VAE and text projection. GGUF does not provide an all-in-one checkpoint loader: files under `checkpoints` are not silently moved or treated as MODEL/CLIP/VAE bundles. VAE and projection files must use the backend's supported non-GGUF formats. LoRA files must be Safetensors; GGUF LoRAs are not supported. Applying a Safetensors LoRA to a GGUF base also remains blocked until that execution path is verified, including either model of a Wan HIGH/LOW pair.

When automatic architecture detection cannot identify a GGUF file, right-click its model tile or installed Library entry and choose **Edit meta…** (keyboard: Shift+F10). Pick the correct existing model family and save. The `.deas.json` sidecar is attached to that exact source file; it does not modify or re-quantize weights. The UI distinguishes your declaration from automatic detection. **Reset to detection** removes the declaration without deleting current provider metadata. Replaced files or malformed sidecars remain blocked until repaired/reassigned. Metadata editing never uploads or runs a model.

The family selects the existing recipe, constraints and companion pickers; it does not add an architecture to ComfyUI-GGUF or make incompatible weights usable. Missing GGUF loader nodes, files or encoder types block Run. H3/LTX audio-in-video connections remain unchanged; this does not add standalone audio generation. Real inference and platform acceptance are recorded separately in [Verification](VERIFICATION.md).

## Session-only pipeline and model drafts (0.1.64, shipped in 0.1.66)

Switching a pipeline or selected model remembers the **last edited** draft, even if you never pressed Run. Returning restores positive/negative prompts, input and last-frame media, ordered prompt images and video/audio references (including trims, stream choices and RefMods), LoRAs, seed/mode, model components, generation options and post-processing. Image editor masks, paint and layer transforms stay with their source. Each pipeline remembers its last selected compatible model; draft identity includes the model category/full path and environment, not just its filename. Project drafts have a separate scope.

This cache exists only in the running app's memory; it does not add localStorage/sessionStorage records or save media/canvases to disk. A full restart clears the per-model cache. The ordinary global last-used preferences below still seed startup, and an unvisited model/pipeline keeps the existing starting-settings behavior. Files must remain available at their original paths; this is not a managed-media backup or a replacement for [Projects](PROJECTS.md).

Explicit project/history/metadata restore takes precedence over cached settings. Its subsequent edits become the next remembered draft. Explicit **Image to Image**/**Inpaint** actions keep the clicked source rather than adopting a cached source. **Reset to defaults…** clears session drafts as well as resetting the editable controls. Switching/restoring does not upload, submit, restart a service or modify queued/running jobs. Recent seed history, Continuity job references, layout and writing-aid preferences remain shared, not per-model drafts.

## Prompt writing aids (0.1.63, shipped in 0.1.66)

Positive and negative Studio prompts show their current length / 16384 at the right of the heading, matching the enlarged editor. Both editors share the same writing aids and prompt value. Counts use the browser textarea’s UTF-16 length limit, not model tokens.

Below **Backend → Language**, enable/disable **Prompt spellcheck**, choose its independent remembered **Spellcheck language**, and enable **Tag autocomplete**. Spellcheck starts on and follows the detected system language until explicitly changed; changing the interface language does not change this choice. **Quick Settings** has immediate, synchronized on/off buttons for both aids. These global writing preferences are not project/run settings and are not reset with Studio defaults.

Spellcheck uses the system WebView’s local dictionaries, not an LLM or a ComfyUI service. No prompt text is transmitted. Linux verifies that WebKit actually loaded a matching Enchant dictionary; when none is installed, Backend → Language shows **Install dictionary** for German, English, French and Turkish. That button downloads the pinned Hunspell pair (size and license are shown first) into your user folder (`~/.config/enchant/hunspell`), without admin rights or a system package manager, then re-checks; if Enchant does not pick it up at once, DEAS asks for a restart. Japanese and Chinese have no published Hunspell dictionary, which is stated instead of offering a download. Nothing is downloaded by merely opening Settings. Native dictionary configuration affects the app’s shared WebContext, including other editors/Comfy when they permit spelling. The current Windows WebView2 bindings cannot select an independent spelling dictionary: DEAS reports this unsupported state (a Logs warning, not an error, since it repeats on every launch) and only supplies HTML language/spelling hints there; no dictionary download is offered on Windows. Platform acceptance limits are recorded in [Verification](VERIFICATION.md).

Tag autocomplete starts **off**. When enabled, it reuses Prompt Forge’s existing native local tag search and model-specific spelling; other generation families use ordinary space-separated tag spelling. A configured environment/root and the Forge tag data are required. Type at least two characters in the current comma/newline-separated tag, select with Up/Down and Enter or Tab, or click a suggestion. Escape dismisses suggestions before closing the enlarged editor. Selecting replaces only the current tag; it never submits a job or rewrites the remaining prompt. Suggestions are optional Danbooru vocabulary, not a claim that every model supports every tag. Nothing is searched while disabled.

Update actions remain clickable. To its left, **Backend starting…** stays visible while the owned backend reports starting. On running, a green check briefly glows/fades and the notification disappears after **3 seconds**, without repeating on unchanged status polls. **Backend** keeps language/folder settings and installation/Owned backend management in their existing locations. A **left-hand menu** selects **Startup optimizations**, **LLM backend** or **Provider authorization** in one consistently styled **right-hand pane**. Without a checked installed environment, Startup optimizations is disabled with an explanatory tooltip. A fresh environment opens the automatic, editable read-only installation review immediately, but only **Start install** authorizes installation. An installed environment exposes **Owned backend** with the existing explicit Start/Stop/Restart/Upgrade/reinstallation safeguards. The backend stays mounted while navigating, preserving polling and the running endpoint handoff. There is no redundant AiO installer or generic Settings navigation button.

Click **DEAS v…** in the footer to open **Backend** and the update confirmation, whether or not the launch-time read-only check found an update. **Upgrade** opens the same question; **Cancel** performs no update. With an installed environment the question asks what to update:
- **Everything** (default): checks the latest application binary first, then upgrades the installed owned backend with the existing pinned-Torch policy.
- **DEAS app only**: only the application binary; the backend is not touched.
- **ComfyUI and node packs**: the ComfyUI checkout, DaSiWa/GGUF node packs and their Python packages under the pinned Torch constraints; no DEAS download.
- **PyTorch only**: shows the exact from → to packages. It is offered only when this DEAS build knows a newer profile of the same kind (CPU stays CPU, CUDA stays CUDA) and the read-only GPU/driver check for it passes. Node packs DEAS did not install block it, because their compatibility with another Torch is unknown. ComfyUI and the node packs keep their checkouts, and other packages are not upgraded. The new profile is written to the plan only after the verify step passes. On failure the plan keeps the old profile, and the error says so; the venv may be partly changed, and **ComfyUI and node packs** reinstalls the recorded profile. This is not a rollback.

Every backend update stops the owned backend first and is refused while Studio jobs are running or settling; nothing is cancelled for it. The question explains that this stops the owned backend; models and media are preserved. If the application binary changed, DEAS automatically closes and reopens after a successful backend update (if installed) and pending project saves. Running native generation, downloads and Library scans defer the restart; failed project saves keep it blocked until saved or explicitly discarded. Without an installed environment, Upgrade updates only the application. See [Application updates](APP-UPDATES.md) for supported binary formats, verification and update limitations.

The compact Backend overview marks a checked installed environment and configured providers. A provider check means **a token is set**, not successful identity verification, license acceptance or guaranteed access. The authorization panel retains its separate verification result. Saving, removing, restoring or refreshing credentials updates the overview.

A media tile opens only the central view panel, without replacing the current input, discarding a painted editor draft or starting generation. Click the **read-only preview image** (Enter/Space also work), or the editor filename below the canvas, to open a read-only overlay with wheel/button zoom and pan. The separate Full view button is no longer needed. **Fit** proportionally fills the available width or height without cropping, including upscaling smaller images; **100%** separately restores natural pixel scale. The area outside the picture is semi-transparent, with no checkerboard. Clicking that backdrop, Escape or the close button dismisses it; picture/toolbar clicks and drag-panning do not dismiss it. Image-to-image and inpaint canvas interaction is unchanged. Choose **Use as input** or an explicit image-edit mode to adopt a browsed item; closing the browsed preview returns to the retained draft/result. Metadata follows the browsed item without silently applying its settings.

For **Image → Video**, right-click an image in the Media dock and choose **Use as input**; for **Video → Video**, right-click a video and choose **Use as source video**. These select the clicked file directly without opening or adopting its preview first. Selection alone does not upload a file or start generation; ordinary left-click browsing remains preview-only.

When the selected checkpoint/diffusion model supports image prompting (Text → Image or Image → Image), right-clicking an image in the Media dock offers **Use as prompt reference** — the same reference as dropping the tile onto the prompt (up to 4; the entry is disabled with the count when full). Applicable **Star/Unstar**, **Use as input**, **Image to Image**, **Inpaint** and **Last frame** actions stay associated with the displayed media. Browsed/source controls use the desktop header or a reserved narrow row; result/editor controls stay below their content. ## Queue lifecycle limits

**Run** stays available while jobs are queued/running, provided the current draft validates. Each press queues a new immutable intent with its captured prompt, settings and seed; Fixed retains the selected seed and Random allocates the next seed immediately, including rapid presses. During work the same control has an adjacent **Stop** action. Native capacity is bounded; active/unknown entries are never evicted to admit more work. Image, video, Post-process and Continuity submissions now use the native Workbench collection rather than the separate diagnostic slot. The collection holds up to 20 session entries; Studio restores it when mounted and polls the held jobs against their original endpoints. Submitted settings remain separate from editable controls, and a Continuity completion is matched by its job ID.

Local output actions use each job's native-captured output directory, revalidated against its original directory identity—not the currently selected environment folder. If that root is unavailable, image results use job-bound native preview/export without invented local paths or Star/Post-process targets. Post-process transfers the actual selected result file into the destination backend rather than assuming that equal folder text proves backend ownership. Unmounting Studio drops frontend preparations that have not reached native Run; uploads already in flight may finish and leave backend copies, but do not authorize a later generation. Run outcomes, including ambiguous IPC failure and immediate terminal results, are reconciled with the native collection without retrying computation or replacing newer observations. Outstanding Run/Stop IPC remains tracked across Studio remounts. An unfenced unresolved reply keeps recovery guarded; Stop advances the native admission generation so older delayed Run requests cannot start after it finishes.

Unknown outcomes and native preparations remain retained; they never authorize an automatic retry. A deliberate new Run creates a separate job. Recovery, pending Stop ownership and serial Continuity processing can temporarily block admission; model/input/dependency validation remains required. Opening Studio reads only the native-held session snapshot for queue recovery; the separate model/prerequisite discovery is unchanged. Collection polling observes existing work without submission, and a collection IPC error does not invent new states for its peers. Neither snapshot nor polling cancels jobs, clears a backend queue, starts services or restores jobs after application restart.

The combined Stop action reuses native targeted pending cancellation and scoped running interruption on held Workbench jobs. Pending cancellation deletes only a correlated pending prompt on the currently owned running backend. It never interrupts a running generation or clears a queue. The separate native-only running-interrupt command uses a per-launch-authenticated DEAS route, not core `/interrupt`, and serializes exact target validation with flag setting under the queue mutex. It requires the inspected ComfyUI source revision `b1a247c9…` (LF/CRLF); unknown or changed sources disable interruption without blocking backend startup. Relaunching the owned backend after updating DEAS installs the adapter; no running user service is restarted automatically by this change. The UI calls the combined native coordinator, not arbitrary per-job endpoint or prompt-ID operations. Unknown outcomes are retained and attempted mutations are not repeated, even after status reconciliation. A confirmed removed pending job is **Cancelled** (×), not failed or still processing; this label is available in all six languages. Existing diagnostic controls and media/output actions remain unchanged.

Clicking **Stop** explicitly authorizes native whole-Workbench coordination over the app's held jobs and disables Continuity Run-all immediately. Unsent frontend preparations are dropped; uploads already in progress may finish but cannot later submit their discarded intent. While it runs, new Workbench admissions are blocked and unsent preparations are discarded. Already submitting jobs settle without resubmission or guessed IDs; pending→running races use the distinct scoped paths. Overlapping Stops share one operation, which finishes even if its callers disappear. Completed products and unknown jobs remain retained. Its result is `empty`, `settled` (all retained jobs terminal, not necessarily cancelled) or `partial` (unresolved work/refusals); an acknowledged interrupt can still be running, so it must not be displayed as completed cancellation. Initially unknown jobs with a known prompt ID reconcile read-only for that invocation; a later explicit Stop may act on a newly known state. No global queue clear, foreign-job cancellation or service stop is permitted. `stopAvailable:true` means this coordinator is supported, not that every backend/source is cancellable. Foreign, unreachable or unsupported jobs retain their actual state with a partial result/error. Repeated Stop never repeats an ambiguous per-job mutation; empty/settled/partial results remain visible in all six languages. See [native Stop details](../src-tauri/README.md#native-whole-workbench-stop).

### Text encoders, VAEs and companion files

The Settings column uses one compact selector style for Pipeline, Checkpoint, aspect, resolution, sampler, scheduler, scaling and other dropdowns. **Checkpoint** lists the scanned models and shares the same selection/default-setting handler with the Models dock: choosing either updates the other. Models without a supported recipe for the current pipeline remain disabled; missing remembered models remain visible and block Run rather than being substituted. Native preparation explains when the backend lists a requested model only under the other loader. Unknown checkpoints retain their existing behavior; family detection is not a universal test of whether all encoder/VAE weights are bundled.

The header detector currently recognizes Qwen3-0.6B (Anima), Qwen3-VL-4B/8B, UMT5-XXL, Wan 2.1/original Qwen Image VAE, Qwen Image 2.1 VAE, and LTX 2.3 audio-VAE/text-projection layouts. Detection uses bounded tensor names, shapes and descriptor/payload bounds; it reads no tensor weight bytes and performs no Python deserialization. Unknown Gemma/LTX video-VAE/H3 and packed variants may still need filename hints or manual selection; this is not universal architecture or successful-loading proof.

Each selector has its own remembered **Matching / All files** switch, off by default. Matching prefers recognized component architectures from the local safetensors header; supported family data declares which architectures fit each slot. For formats/architectures not recognized by the header detector, existing filename hints remain a fallback, not verified compatibility. **Automatic · filename** shows the exact recommended file used by the intent; choose an explicit filename to override it or Automatic to return to the recommendation.

**All files** lets you manually choose any scanned file in that slot's category: `text_encoders`/`clip` for text encoders/projections and `vae` for video/image/audio VAEs. It does not search arbitrary host paths, turn a checkpoint into an encoder, add new loader/recipe support or claim compatibility. Turning the switch on widens the list but never automatically picks an unrecognized file. Wrong components can fail at backend loading; existing safe-name, backend availability, node and intent checks remain mandatory.

Manual choices are never silently replaced when filtering is restored or the file disappears: the unavailable/filtered entry stays visible and blocks Run until explicitly corrected. The four switches are independent. Choices and switches use the existing global last-used preference store and defaults reset; they do not alter already prepared/submitted jobs. The current baseline project format does not save these optional settings: opening a project resets them locally, closing it restores the global choices. Selecting, switching or rescanning does not load model weights, run inference or restart the backend. Use Models → Reload after adding/replacing component files.

### MOSS-Image generation

Node readiness follows the selected conditioning path: without prompt-picture references MOSS requires `CLIPTextEncode`; with references it requires the bundled `DEAS_ImagePromptEncode` adapter instead. Removing the last reference restores the plain text-node requirement. Missing active nodes still block Run; an unused text node no longer blocks the reference recipe.

The header-detected **MOSS-Image** family supports **Text → Image** and ordinary denoise-based **Image → Image** through the shared image recipe. Select the diffusion model in Checkpoint, then choose its dedicated Qwen3.5-9B text encoder (`moss_image` loader type) and Flux2 VAE under **Model files**. Text-to-image uses the core `EmptyFlux2LatentImage` node; image-to-image encodes the chosen source with that VAE and retains the selected denoise. Canvas edges must be multiples of 16. This is not instruction-edit/reference conditioning, and MOSS control adapters are not enabled.

Starting sampling values follow the Comfy-Org t2i template (25 steps, CFG 2.5, `er_sde`, `simple`), but this bounded adapter omits its SLG and prompt-upsample stages; these are starting values, not verified equivalent image quality. LoRAs, inpaint/masks, inserted image layers, refine/post-processing, custom sigmas, padding/upscale and model-patch options are not supported by this first MOSS adapter and are rejected rather than silently ignored. Disable those options before Run. Remembered unsupported choices remain visible with a per-feature **Restore … defaults** action; selecting MOSS does not silently erase them. The Run button also checks the selected variant’s nodes and the backend’s `moss_image` CLIP type. A source image not aligned to /16 stays blocked with Off or unchanged Auto scaling; explicitly choose a visible resize such as Fit, Crop or Target rather than letting VAE encoding crop pixels implicitly.

Header detection identifies the MOSS diffusion model and supported full-width Qwen3.5-9B/Flux2 companion signatures. The locally inspected packed `mossImage_sft_txt_int4.safetensors` encoder remains **unknown**: Matching does not claim compatibility. An explicit category-scoped **All files** choice can select it, but selection is not successful loading. Required nodes/components are checked against the final emitted graph; an unused checkpoint loader or generic empty latent is not a MOSS requirement. Later fixed-seed 512x512 GPU reference-effect runs provide narrow MOSS execution evidence; see [the recorded model/settings limits](VERIFICATION.md#unified-image-reference-wiring-0147). Other variants, ordinary i2i quality, Windows runtime and broad image-quality/resource acceptance remain open.

### Post-Processing

Generate's **Post-Processing** dock tab is the SwarmUI Refine / Upscale step. **Refine / Upscale after every run** (off by default) adds a second pass to each Run: an optional upscale model from the configured `upscale_models` folder, a lanczos resize by the **Upscale factor** (1–4, each edge snapped to the model's grid), then resampling with the same model, prompts and seed at the **Refiner strength**. **Post-process** sits in the preview toolbar while **Image to Image** or **Inpaint** is active and applies that step alone to that picture (the edit source or the shown render), without a new first generation. Other pipelines do not offer it, because their active model may not be an image model. The image edit buttons are **Image to Image** and **Inpaint**; the settings column names the input picture by file name only (folders and the `[output]` suffix are in its tooltip); refine and upscale moved into this tab.

**Tiled refine (DaSiWa Tiled Diffusion)** samples that second pass in overlapping latent tiles instead of one large latent. The tile is the picked model's native size (SDXL 1024×1024, LTX 1280×704, …) snapped to its grid, the overlap an eighth of the shorter tile edge (at least 64 px); the `DaSiWaTiledDiffusion` MODEL patch runs every denoising step tile by tile and blends the overlaps with positive pyramid weights, so there is no seam to fix afterwards. The toggle is enabled only when the backend lists that node (DaSiWa node pack); the first pass stays untiled. ControlNet is not supported on the tiled pass.

#### Original and processed image products (0.1.51, shipped in 0.1.52)

An image Run with **Refine / Upscale after every run** saves two encoded products: **Original** is the complete generated image immediately before refinement (after full inpaint composition, where applicable); **Processed** is the refined result. Original uses an `_original` filename-prefix suffix; Processed retains the existing prefix. Both savers use the selected PNG/WebP format and compression when the metadata saver is available; core-only saving remains PNG. No extra generation pass is used to obtain Original. Runs without refinement retain their existing single-output graph and naming.

Select either labelled product in the queue or above the result. Each retains its own filename and existing output actions. Where the job's checked local output root is available, **Slider** compares these two products, not the unrelated image-to-image input. Without that local root, select each product for native PNG preview and **Save As**; native output transfer remains PNG-only. WebP files remain accessible through the checked local output/media path, not the PNG-only transfer API. A standalone **Post-process** action without a `refine` chain is unchanged; it does not create a duplicate baseline copy.

If refinement fails or is cancelled, any baseline already reported in correlated backend history remains selectable/exportable, and the job stays failed/cancelled. **Limitation:** ComfyUI schedules the two saver branches independently; saving Original is not a guaranteed prerequisite of refinement. A failure before its saver executes can leave no baseline product. Strict baseline-before-refinement publication needs a later sequencing slice; this implementation does not claim it. Existing input files are never overwritten, and DEAS does not delete completed products as cleanup.

Single-image model-dependent refinement remains inside ComfyUI. For image series, separate queued image jobs avoid retaining one large batch tensor; throughput advantages are not benchmarked. Full-video restoration/upscale/interpolation/HDR needs the separately planned bounded streaming worker, not a complete ComfyUI frame batch. See [implementation scope and remaining acceptance](PLAN.md#42-video-post-processing-tve-and-paired-products).

### Image editing

Drag an Input/Output image from the Media dock onto the picture to insert it at its original pixel size (scaled down only above 8192 px), centred where you drop it. Select its layer thumbnail to move it, resize its corner with aspect preserved, or use arrows / + / − / Delete. Image layers can be hidden, reordered and removed; only visible inserts are submitted (up to four). The **Base image** is also editable: select its row to paint, move, resize, hide or raise/lower it among the inserts. The canvas dimensions stay fixed. Drag image rows onto other image rows to reorder them; mask rows can be reordered within their own mask stack. Raise/Lower and arrow / + / − keys remain available without dragging. The base row stays available for showing it again after hiding. Inserts currently composite opaquely; transparent cutouts are not supported.

With **Base image** or an inserted image selected, **Brush** adds colour strokes and **Erase** removes those added strokes (not the original file pixels). **Clear** removes the selected picture's strokes without resetting its position or size. Painting uses that picture's own pixels: a colour field, hex value and a palette of standard colours sit in the toolbar. Run flattens painted inserts to PNGs. If the base is painted, transformed, hidden or reordered, Run instead snapshots the complete visible image stack into one source-sized PNG and uploads it as the input image, without pasting the inserts twice. The inpaint mask remains a separate PNG and is never baked into that input image. Original files are not changed.

**Inpaint** provides up to four independent mask layers with selectable thumbnails, Brush/Erase, a synced diameter slider and number field (1–1024 source pixels; Ctrl+mouse wheel resizes the brush while Brush/Erase is active), round/square brushes and a black–white **Mask value** slider (white = full repaint, default). Clear affects the selected mask. Visible masks combine into one white-repaint/black-preserve PNG; **Opacity (%)** controls only the mask overlay's visibility (75% default; saved user values are retained; value shown beside the slider; it snaps to 10, 25, 50 and 75 % when dragged within 3 % of them). **Magic wand** adds the connected area of similar colour around the click to the selected mask, Alt+click removes it; **Tolerance** (0–255, default 32, per RGB channel against the clicked pixel) sets how far the area grows, so it stops at visible edges. It reads the source picture only, not inserted layers. Wheel zoom follows the cursor; Fit, 100%, zoom buttons and Pan/middle-drag change the view, never source coordinates. Masks can be raised/lowered like image layers; the exported mask is their union, so the order is cosmetic.

**Outpainting:** in Inpaint a thin outline marks the source frame, the area the job processes. Pictures can be moved partly outside it; only what lies inside the frame is sent. Parts of the frame that no visible picture covers are outpainted: they are added to the mask (even without painting one) and start neutral grey, like ComfyUI's ImagePadForOutpaint. While the pictures cover the whole frame, the job is the same as before.

**Inpaint only masked** is opt-in. **Mask Shrink Grow** adds 0–512 source pixels of context around the visible masks (default 8 when enabled); 0 still enables a tight crop. The crop is processed at the active model's native pixel budget with model-aligned dimensions and its own aspect ratio, then resized back and composited into the original full-size image. Larger margins give more surrounding context; smaller margins concentrate detail. The crop also includes the finite blur support so softened edges are not clipped.

**Mask Blur** accepts integer radii 0–31 (default 4; examples: 0, 4, 8, 16), using the same Gaussian kernel and sigma as SwarmUI, limited to the core ComfyUI node’s supported radius (31 rather than SwarmUI’s 64). It softens both the sampling mask and final blend. Default 0 disables it, independently of crop mode. Both options appear only in Inpaint, preserve inserted image layers and use core ComfyUI nodes without an extra node pack.

Entering or leaving side by side (after Run of an edit) refits the editor picture into its column, also after zooming. While Image to Image or Inpaint is active, every queue entry you pick opens beside the editor, so masks and edit controls stay visible. Picking an edit job when no draft is open (after ✕ or after browsing another picture without masks or inserts) brings its source picture and mode back into the editor; masks closed with ✕ are not restored. In **Slider** compare the wheel zooms both pictures together at the cursor, middle-drag pans, double-click resets; the divider stays put. **Slider** (compare) and **Full view** sit with the edit buttons on the left of the render's toolbar. Clicking a render or a browsed picture (or **Full view**) opens it over the whole window: the wheel zooms at the cursor, dragging pans, Fit/100 % reset the view, Escape or ✕ closes it. The edit draft survives Generate/Workspace map and top-level tab switches, edit-mode changes and reviewing queue results. **Return to edit draft** restores it after submission. Selecting another source resets the draft; masks are not saved across application restarts. Clear/delete have no undo. Inpaint refuses source sizes outside the selected model family's resolution grid rather than silently changing pixels; resample first. Submitted mask/insert snapshots do not change when the draft is edited during upload. The originals are never overwritten.

When all references are labelled pictures, the tab also lists **Cast & scene cards** — one per Character, Place and Style; **Read** lets a vision model describe it from its pictures, and you can edit or write the card yourself. For H3 REF2VA group pictures, choose **Characters 2 + 1 (left → right)** or another offered group in the reference's Forge label. The numbers describe where each character stands, not picture order; `2 + 1` puts Character 2 on the left. The seven groups cover pairs among Characters 1–3 and `1 + 2 + 3`. Choose **Left → right**, **Top → bottom**, **Front → back**, or **No spatial order**. These describe positions in the picture, not timeline order. More numbers become available as needed, up to 32. Selecting a different picture label resets these overrides. Cast cards follow the actual selected people, and packs preserve the selection/order. Other picture kinds do not expose this editor. Combined picture kinds remain unimplemented; frame-mode cards use the separate controls below.

**Pose cards:** label an H3 REF2VA picture **Pose**, then open the Prompt Forge tab. If the picture already lives in the backend input folder, its **Pose · Picture N** card appears beside the Cast/scene cards. Boxes override the number/order list. ### Learned video latent upscale (0.1.64, shipped in 0.1.66)

For generated **MiniMax H3** and **LTX 2.3** videos, open **Generate → Post-Processing** and enable latent upscale. It is off by default, independent of image refinement and LTX's existing 2-/3-pass sampling controls. The chosen model operates on the final generation latent before video decoding and Video Combine; it is not a TVS effect on an imported encoded video. Sampling, reference conditioning, audio and source-resolution continuity checkpoints keep their existing ownership. Disabling the option restores the previous graph and output count.

Both families need a compatible learned model in the configured models root's **`latent_upscale_models`** folder. H3 uses `minimax_h3_latent_upscaler_3d_conv_v1_bf16.safetensors` (or its supported FP16 variant); LTX 2.3 uses `ltx-2.3-spatial-upscaler-x2-1.1.safetensors`. These are not interchangeable with each other or image upscalers. Enabling with no compatible model offers the existing **Library** in a popup. Review the offered files and native plan and explicitly authorize the download. Cancel/Escape does not download or start generation. Closing an already running download leaves the native transfer running; reopening the popup recovers its progress and explicit Cancel control before enabling another start. After successful completion, availability is refreshed; unresolved or removed models still block Run. No weights are bundled, downloaded automatically or replaced with interpolation. Provider access, model terms, space and the actual backend's compatible node versions remain prerequisites.

LTX post-upscale is exactly **2×** after its last sampling pass and leaves the audio latent unchanged. H3 offers a scale plus independent refinement steps/denoise (node defaults 2×, 1 step, 0.2); target edges follow the H3 node's 32-pixel, ties-to-even rounding. H3 denoise 0 skips diffusion refinement but still performs learned latent upscale. **Upscale refine steps** and **Upscale refine strength** belong to this refinement pass only; they run after the normal sampling and are independent of the generation steps.

H3 also has **☰ More upscaler options**, a collapsed menu under those fields with the remaining `DaSiWaH3TiledUpscale` inputs: refine CFG and scheduler (scheduler names come from the running backend), upscaler precision, spatial tiling, temporal chunking, memory planning with its reserve, memory budget (0 = automatic), Spike Guard with sensitivity/strength/mode, and Continuity soft refine with its mask strength. Every field starts at the node's own default; only values you change are sent, so untouched options leave the graph exactly as before. **Reset to node defaults** clears them. Changed values appear in Run Plan and are restored from Recent history. Continuity soft refine has no effect without active Continuity, and Spike Guard is experimental (validated by the node pack only for `3d_conv_v1`). LTX has none of these options: its upsampler node takes only the model. The same H3 model/conditioning and prepared continuity context feed the node; the original audio stream is retained. This does not add another initial generation pass or claim arbitrary video timing conversion. Run Plan shows the captured settings and enlarged canvas; later edits do not modify a submitted job.

Results retain separately identified **Processed** and **Original** encoded videos with distinct filenames. Original is decoded from the final pre-upscale latent, including H3 timeline preparation, not an input reference or thumbnail. Upscale consumes that latent directly rather than decoding the baseline file. The processed result remains primary; role selection switches the displayed video. Completed products remain attached to failed/cancelled jobs. As with existing image pairs, independent saver branches do **not** guarantee that Original is encoded before every possible upstream upscale failure; strict baseline-first ordering remains open. General native video Save As/export and target-player acceptance are separate from this graph integration.

**Compatibility limit:** H3 Continuity capture with **New segment only** is blocked when latent upscale is enabled because the current nodepack's capture validation permits only one matching Segment Decode. Choose full-timeline output or disable latent upscale; DEAS does not patch the installed nodepack or drop the baseline. H3 image editing, Wan upscale, learned-model quality, seam quality, peak memory and Windows native runtime are not established by this feature. Temporal chunking bounds some H3 intermediates, not total clip-sized latent storage. See [the plan](PLAN.md#41-video-h3-director-and-playback) and [verification](VERIFICATION.md#learned-video-latent-upscale-0164-shipped-in-0166).

### REF2VA continuation references

In H3 Video → Video and Multi-reference → Video, **Use current references for continuations** is off by default, matching the Director. ### TVE post-processing on the backend (0.1.67)

Every video pipeline (LTX 2.3, Wan 2.2, MiniMax H3) can run the TrueVideoEnhancer stages on the decoded frames before the final encode. Open **Generate → Post-Processing**; the controls marked with a **TVE** badge are pulled from TVE and are all off by default, so an untouched Run sends exactly the graph it sent before. The stages run in the order of the owner's "Post Processing" workflow subgraph:

1. **Upscale model** — a file from `upscale_models` through core `UpscaleModelLoader` → `ImageUpscaleWithModel` (the model's own factor, 2× or 4×).
2. **RTX refine (NVIDIA)** — `DaSiWa_RTX_UpscalerRefiner`: **Denoise** and **Deblur** (each Low/Medium/High/Ultra) and **RTX upscale (VSR)** with mode VSR / High Bitrate / Streaming Medium / Streaming Ultra, quality and a 1–4 scale (`resize_type` Scale, 8-pixel alignment). The backend's listed modes decide which presets are offered; the node must be installed (`DaSiWa_RTX_UpscalerRefiner` in `object_info`).
3. **Frame generation** — either **RTX Frame Generation (NVIDIA)** (`DaSiWa_RTX_FrameGeneration`, frame-rate multiplier 2–16, LOW/MEDIUM/HIGH) or **RIFE** (core `FrameInterpolationModelLoader` → `FrameInterpolate` with a file from `frame_interpolation`, multiplier 2–16). The combine's frame rate is the source rate × multiplier.

With any TVE stage enabled the job produces **two real encoded products**: **Original** (the decoded video at the source frame rate, `_original` prefix suffix) and **Processed** (the chain's result). Both appear in the queue, the results and the Run Plan **TVE post-processing** stage; a learned latent upscale keeps its own pre-upscale baseline, and the TVE chain then follows the latent upscale. The intent carries the stages as `videoPost` (`upscaleModel`, `useMmap`, `rtx{denoise,deblur,upscale{mode,quality,scale},chunkFrames}`, `frameGeneration{engine rtx|rife,…}`); native validation (`jobs_video_post.rs`) bounds every value, preparation checks the upscale/RIFE model names against the backend lists, and Run stays blocked while RIFE has no model. An **RTX memory** card appears while an RTX stage is enabled: **Disk fallback (use_mmap)** reaches both RTX nodes (the node's last storage tier for batches that exceed RAM) and **Frames per chunk** (1–1024, default 16) sets the RTX Upscaler & Refiner's internal chunk size. Neither shrinks the full batch allocation — the node still allocates the complete IMAGE output, so long videos need `use_mmap` or fewer frames. Generation metadata and Recent history show the enabled chain; restoring a history record restores the TVE controls.

The **TVE** tab's **Enhance on the backend** panel applies the same chain to the inspected existing video (source picked with the OS chooser or from the Media panel, see the TVE workspace above): the retained source is copied into the owned backend's input folder natively (`native_video_post_upload`, the path never reaches the webview), a `video-enhance` intent (`LoadVideo` → `GetVideoComponents` → chain → `DaSiWa_EnhancedVideoCombine`, source audio mapped, codec/container/bit depth/quality/audio from the panel, default prefix `raw/tve/`) is submitted to the shared native session and appears in the **Studio queue** with progress, preview and export. The panel polls that job itself (`native_workbench_poll`), so its own **Queued → running → failed** state and the backend error are visible without opening the Studio queue; a job that leaves the queue is reported as unknown instead of staying queued. The imported source is the baseline and is never rewritten. Model/RTX output geometry is only known at run time, so saved first/last-frame PNGs of such jobs are accepted at their decoded size within the usual caps. Not covered: HDR and restoration beyond the SDK's denoise/deblur.

## Output naming

**Generate → Options → Output naming** saves an extensionless naming template relative to **Output/raw/**. The `raw/` base is fixed and added outside the template; custom templates and placeholders keep their meaning. Default: `%type%/%date_yyyy-mm-dd%/%time%-%seed%-%model%`. Variables are resolved once per submitted job: type (`image` for the current image recipes), local date (`yyyy-mm-dd`), local time (`HH-MM-SS`), the actual seed and the model basename without extension, sanitized to ASCII letters/digits/hyphens (up to 120 characters).

Example below the selected Output root: `raw/image/2026-10-18/14-30-05-42-My-Model-00001.png`. Star changes only `raw/` to `starred/`, preserving `image/2026-10-18/…`. The owned backend installs the adapter on its next start (restart a previously running backend). Video saves follow the same pattern: `video/…-00001-audio.webm` plus `-00001-audio-first-frame.png` when frame export is on. The legacy `%date_yyyy_mm_dd%` token is rewritten to `%date_yyyy-mm-dd%`; the rest of a custom template is kept. **Default** on the Output naming and Output format cards restores that card's defaults only. Custom subfolders and literal ASCII letters/digits, `_`, `-` and `.` are supported; traversal, absolute/device paths and unknown variables are rejected before submission and checked again natively. ## Prompt Forge canvas handoff

Prompt Forge reads Generate's current effective canvas, including model alignment and adopted-source processing. Choosing an aspect or receiving a writer result changes only Forge's draft. **Send to Generate** applies the result's consumed dimensions as **Fixed**, together with the chosen prompt text; Run remains a separate action. Seed, model, sources, masks, references, history blockers and submitted jobs are preserved. Project drafts use normal autosave and retain unsaved protection if saving fails.

N/A transfers text only. Auto uses the actual valid Generate canvas; an unavailable context stays unresolved. Custom uses Settings' finite 1–100 ratio components. The displayed dimensions include bucket/grid snapping. A source/inpaint/scaling path that cannot produce those exact dimensions blocks canvas Send; the separately labelled text-only action keeps the existing processing controls. Changed writer/model/mode/endpoint/context or layout revisions make an older result stale instead of rebinding it to new dimensions. See [Prompt Forge usage](PROMPTING.md#prompt-forge) and [target-specific status](VERIFICATION.md#u-01-prompt-forge-canvas-handoff-0155).

## Prerequisites and troubleshooting

MiniMax H3 references uploaded into `deas-inputs/` do not appear in ComfyUI's top-level image combo. DEAS accepts these references after path validation; the backend loader/Director checks the actual file. If an older app reports `Diagnostic images are not available on this backend: deas-inputs/…`, relaunch the rebuilt app; no backend upgrade is needed for this fix.

Use a checked running backend, compatible models and required nodes. Run snapshots immutable settings; edits do not mutate active jobs. Read blockers before retrying and never silently repeat uncertain submissions. Job-scoped cancellation, persistent editor projects and broad Windows/model acceptance remain open.
