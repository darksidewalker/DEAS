# Native authentication plugin

The canonical current contract is [Download and authentication plugins](DOWNLOAD-PLUGINS.md). This document replaces an earlier session-only API draft; `native_auth_clear` and the old `AuthStatus.providers` envelope are not supported commands.

`src-tauri/src/auth.rs` owns exact-origin credentials independently of catalogs and network transports. Current commands are `native_auth_status`, `native_auth_set`, `native_auth_remove` explicit `native_auth_restore` and `native_auth_verify`. Status returns an array; set/remove/restore return one metadata object with `providerId`, `configured` and `persisted`. No token is read back. Presence is not verified login, entitlement or license acceptance. `native_auth_verify({providerId})` returns only `{providerId,status}` with `verified`, `rejected`, `unavailable` or `unsupported`. The panel checks a configured token on opening/provider change and after saving/restoring; Refresh retries. Only `verified` shows a green checkmark; results are session/view evidence, not persisted account state.

Saving a token defaults to OS credential-store persistence; unchecking the option keeps it session-only. Desktop startup automatically restores saved official-provider tokens, and the authorization panel reads metadata on opening. Explicit restore remains available for retry after unlocking the store. Vault failures leave the provider unconfigured, without plaintext fallback or secret error details. Official origins are fixed: HF `https://huggingface.co`, CivitAI `https://civitai.com`, GitHub `https://api.github.com`. Native-only custom accounts require explicit `custom-…` identities and exact approved origins; catalogs never register credential scopes automatically. The current UI supports official providers only.

Native consumers use `AuthState::credential(provider_id, exact_origin)` or the scoped `authorization` helper. Download redirects disable automatic following and permanently strip authorization after an origin change. Credentials do not enter catalog/project data, URLs or logs. Best-effort owned-buffer clearing is not a cryptographic zeroization or malicious-frontend sandbox guarantee.

Identity checks send a bearer header to fixed HTTPS endpoints: [Hugging Face `/api/whoami-v2`](https://github.com/huggingface/huggingface.js/blob/main/packages/hub/src/lib/who-am-i.ts), [CivitAI `/api/v1/me`](https://github.com/civitai/civitai/blob/main/src/pages/api/v1/me.ts) and [GitHub `/user`](https://docs.github.com/en/rest/users/users#get-the-authenticated-user). HTTP 200 and the provider's identity schema are required. HTTP 401 means rejected; 403, rate limiting, redirects, malformed bodies, timeout and transport failures mean unavailable, never a false invalid-token diagnosis. Requests disable environment proxies and redirects, have an eight-second full-request timeout and a 64 KiB response limit. No content mutation or download is requested; providers may still update access logs or token last-used metadata. Verification proves authentication only, not gated/private resource permission. No profile data is returned to the frontend.

Tests in `src-tauri/src/auth_tests.rs` exercise session and injected-vault semantics without touching the user's real keyring. Permission wiring lives in `src-tauri/permissions/downloads.toml` and the local main capability. See [verified scope and remaining gaps](VERIFICATION.md).
