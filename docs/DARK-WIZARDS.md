# Dark Wizards

**Studio → Dark Wizards** holds guided helpers for common jobs. You give a wizard a picture and a few words; it picks a fitting installed model, the pipeline, the prompt and the output size, and **prepares Generate**. Nothing starts on its own: Generate shows the prepared draft, the Run Plan shows exactly what would be submitted, and you press **Run** there — or press **Prepare and run** in the wizard, which asks Generate to start that same draft (see below). A wizard run is an ordinary Generate job in the ordinary queue.

The tab is in Advanced's top band; Beginner reaches the same wizards as the **Wizards** page of its band (see [In Beginner](#in-beginner)).

## Replace

Swaps a person, object or detail in a picture for something else — described in words, or taken from a second picture.

1. **Picture to change** (B) — drop a PNG, JPEG or WebP file on its area, paste one (Ctrl+V anywhere on the tab), or press its **Choose…**. A file copied in a file manager is used from its own location. A picture pasted as image data (for example copied from a browser) is first saved to the backend's Input folder, the same way the Media dock's paste does.
2. **Object to put in** (A, optional) — a picture of what should go into B: a person, a product, a piece of clothing. Paste and drop go to the highlighted area; after B is set, the object area is highlighted. Click an area to choose where the next paste goes; **Remove** clears it.
3. **Replace what** and **With what** — for example *the red car* and *a blue bicycle*. With an object picture, *With what* is optional and may name the object in it (*the dog*); without it the prompt says *the main object*.
4. **Method** — the wizard selects the first method with an installed model; you can switch when both are available. Both methods prefer the same Qwen Image 2.1 / 2.1 Turbo model, so switching keeps the selected model:
   - **Reference edit (Qwen Image 2.1)**: B becomes the first prompt reference (`image 1`) of a text-to-image edit in Generate's **References**, A the second (`image 2`). The prompt reads *Replace the red car with a blue bicycle. Keep everything else in the picture unchanged.*, or with A *Replace the red car in image 1 with the dog from image 2. Keep everything else in image 1 unchanged and match its lighting and perspective.* The output size keeps B's aspect ratio at the model's default pixel count, on the 32-pixel grid Qwen reference encoding needs (the first reference fixes the output geometry).
   - **Paint a mask (inpaint)**: Generate opens B in **Inpaint**. With an object picture and a Qwen model, the wizard hands over the **reference edit** on the same model instead and says so: a masked edit with both pictures as references kept the old object in tests, while the reference edit replaces it. Paint over the area that should change, then press Run; Run stays disabled until a mask is painted. Preparing sets Generate's Inpaint strength to 1 so the masked area is redrawn completely (at a lower strength the old object's shape and colour stay), and Mask blur to 4 px. **Prepare and run** makes the mask for you with SAM 3.1 (see step 6). Inpaint keeps B's size, so B must already lie on the model's grid (32 px for Qwen with references); the wizard says when it does not and offers **Crop to W×H**: it saves a centred crop on the grid as a new picture in the Input folder (named after the original plus `-grid-W×H`, never overwriting a file) and uses that copy as B. Only the few edge pixels past the grid are cut — at most one grid step less per side in total, split between both edges — and nothing is resampled, so the kept pixels stay exact; the original file is not touched. A picture too small to crop onto the grid is named as such. Without the crop, Generate blocks Run until the picture is resampled.
   - When no Qwen model is installed, **Paint a mask** falls back to a Flux.2, Z-Image, Flux.1 or SDXL model with *With what* as the prompt. These models cannot read the object picture; the wizard says so and uses only the text.
5. **Model** — the installed models that fit the method, in the wizard's preference order. Models whose family DEAS does not know are never offered. **Look again** beside the list checks the model folders again, for example after copying or downloading a model.
5. **Prepare in Generate** — switches to Generate with the prepared draft. If Generate cannot use the chosen model (for example the file was moved), the wizard shows why and nothing changes in Generate.
6. **Prepare and run** — prepares the same draft and asks Generate to start it, through Generate's own Run path: the same input capture and uploads, the same prerequisite and grid checks, the same queue, history and Stop. The wizard does not submit anything itself. While the job runs it shows the step counter and the sampler preview with a **Stop** for that one job; afterwards it shows the finished picture with its size, model, seed and duration, and **Show in Generate** opens the tab with the job and its output. The result also appears in Generate's queue and in Media, like any other job. This button needs the desktop app.
   - **With Paint a mask**, Generate first finds the mask with SAM 3.1, using *Replace what* as the target; the found mask grows outward by 32 px and gets the 4 px soft edge, so the replacement is not squeezed into the old object's outline (the same text-to-mask path as Generate's own SAM **Mask** button, with Generate's selected SAM checkpoint and threshold — Generate's own SAM targets field is left as it is). Commas or semicolons in *Replace what* make one mask layer per part (*the hat, the scarf*). All parts get the same *With what*: the wizard says so (*All 2 targets (the hat, the scarf) become …*), and to give each part its own replacement you run the wizard once per part. On Qwen Image 2.1 (full model) the masked edit runs at CFG 4 instead of the model's usual 1: at CFG 1 it often only erased the old object (*the phone* → *a red apple* left an empty hand), at CFG 4 it drew the replacement in every measured run. Qwen Image 2.1 Turbo and the other models keep their own CFG; Generate shows the value, and you can change it there before pressing Run. The wizard shows *Finding the mask with SAM 3.1…*; when a mask was found, the inpaint run starts as above. If SAM finds nothing, nothing is drawn: the wizard says so, the draft stays prepared in Generate, and you can paint the mask there and press Run. The button needs *Replace what* and stays disabled with Generate's SAM reason when no SAM 3.1 checkpoint or no `SAM3_Detect` node is available (see SAM 3.1 masking in the [Studio guide](STUDIO.md)). The mask is only found after jobs already running in Generate finish, and Stop appears once the drawing job is queued. A picture to change from outside ComfyUI's Input/Output folders is uploaded to the backend when Run starts, as references are.

Preparing selects the model like a click in the Models dock (its remembered settings return), clears that draft's LoRAs, replaces the picture to edit / prompt references and the positive prompt, and leaves the negative prompt, seed, sampler and post-processing as they are. Check the Run Plan before Run. Components the model needs (text encoder, VAE) are checked by Generate as usual.

### Replace in a video

The picture to change can also be an MP4, MOV, WebM or MKV video (drop, paste or Choose…, as for a picture; the object picture must stay a picture). The wizard reads the clip, takes its exact first frame with the same FFmpeg frame path as Media Analysis, saves it as a new file in the Input folder and shows it as the picture to change, with the clip's name, size and length below it. Then it works in two steps:

1. **Edit the first frame** — every image method above works on that frame (Reference edit, Paint a mask, the object picture, Crop to W×H).
2. **Video method** — two methods, chosen from what was measured (see [verification](VERIFICATION.md#dark-wizards-replace-for-videos-in-the-wizard-ux-22c2-0327-2026-11-24)):
   - **Edit video (LTX 2.3)**: LTX video-to-video with the clip as guide (source strength 0.2) and the edited frame as first frame. It keeps the clip's camera and motion and works best for still or slow shots. In strongly moving shots the old object comes back after about a second, and the clip's sound is not kept.
   - **Re-animate from the edited frame (MiniMax H3)**: H3 image-to-video from the edited frame. The replacement stays, but the motion is new and does not follow the clip; H3 makes its own sound.

   The wizard says plainly that strongly moving shots are not reliable yet with either method. It uses the first 5 seconds of the clip at most (the clip's own length when it is shorter), at the video model's usual pixel count in the clip's aspect, on that model's 32-pixel grid.

**Run both steps** edits the frame through Generate and, when that picture is done, hands the edited frame to the chosen video method and runs it there — both are ordinary Generate jobs in the queue with their Run Plan, Stop and history. **Edit the first frame** runs only step 1; after any finished frame edit, **Run the video step** reuses that edited frame (for example to try the other method) without editing the frame again. The video result plays in the wizard and is in Generate's queue and Media. A video method without an installed model is greyed out with *No installed model for this video method*. The video model list is sorted by the method's family order, then Turbo/distilled/int8/fp8 files first, then by name (so the default is the faster variant of the family); pick the model you want before running (an H3 base model runs at its family's starting settings, a Turbo model at its own).

### In Beginner

**Wizards** in Beginner's band opens the same wizard. **Prepare in Generate** switches to Beginner's **Generation** page; **Prepare and run** stays on the wizard as in Advanced. Only models Beginner can use itself are accepted (the same ones its Models page offers); any other choice is refused with a note and nothing changes. What Beginner shows of the prepared draft:

- **Reference edit**: the wizard's prompt pictures are listed in the composer (*Wizard pictures: …*), and **Quality** reads *Wizard size 1216×672* — the output size the wizard computed; picking another Quality returns to Beginner's own sizes. The wizard size is not remembered as Beginner's Quality across restarts.
- **Paint a mask**: the composer says *Masked edit (inpaint)* and the picture opens in the Inpaint editor, where the mask can also be painted by hand.
- **Clear wizard draft** removes the prompt pictures and the masked edit, back to a plain picture-to-picture draft.

The wizard clears Beginner's LoRAs for that model, like Advanced's draft. Leaving Beginner returns Advanced's own references and edit mode, as for every Beginner draft.

### When no model fits

The wizard says which model it prefers and offers **Find in Library**, which opens the Library catalog filtered to that name. Downloads stay in the Library with its license and consent steps; the wizard never downloads anything. After installing, press **Look again**.

## What a wizard is

A wizard is a data entry in `src/wizards/builtin.json`: its input fields, whether it takes an object picture and, per method, the accepted model families in preference order, the families that can read the object picture, the Generate pipeline, whether the picture is a reference or the picture to edit, the edit mode and the prompt templates (`{field}` required, `{field|fallback}` optional). DEAS validates these entries (known families only, matching pipeline/source/mask) and ignores invalid ones. The wizard only reads the model index, describes the chosen file and asks Generate to prepare a draft — and, only when you press **Prepare and run**, to start it; it never uploads, compiles or submits jobs itself, and it follows just the job its own hand-over started.

## Movie Maker

**Movie Maker** (below *Replace* in the wizard list) makes a film in four steps, shown as numbered steps at the top (a step gets a ✓ when it is done; the next step is highlighted and a line under the steps says what to do next; *How Movie Maker works* opens a three-line summary): **1 Idea and media → 2 Plan → 3 Scenes → 4 Film and music**. The least you need is a few words of idea and, if you like, the pictures, clips or sound that belong in the film — the planner suggests the scenes and places your media in them. (0.3.44 reworked the layout; 0.3.43 replaced the earlier cast stage with scenes.)

1. **Idea and media** — title, aspect ratio and the idea/story in your own words. The aspect list is Generate's own (the same control and ratios as Generate's resolution settings, without *Custom*); **Auto** hands each scene over with Generate's auto aspect (first reference picture, else the model's default canvas). **Add media** opens Generate's own media panel: pick a file and press *Add to the movie* (or drop files on it). Each medium is a small card with an optional note — *who or what is it?* — and **Describe pictures (n)** has the chosen planner model describe the pictures you left without a note, through Media Analysis' describe command (it needs a model that can see pictures; a model on another computer only gets the pictures after you confirm the host). Clips and sound get a note only from you. Each medium is a card showing the whole picture (fitted, never cropped), its note and where it is used (*Auto — the plan places it*, or *In Scene 1, Scene 3 · Reference*). **Click a medium** to open its panel: the medium in Generate's preview player (a picture opens the full-window viewer on click), the full note, **Use in** — tick one or several scenes, or *Auto* to let the plan decide — **As** (reference, first frame, last frame; what the scene's model can take) and, for a reference picture, the Director **Label** (character 1–8, place, style, pose, custom). You can also **drag a medium onto a scene card** to add that scene. What you set is binding: the plan only places media left on *Auto*. Where a medium is used is read from the scenes themselves, so changes made in a scene's *Inputs…* show up here too. MiniMax H3 does not mix frames and references in one take; a scene that would mix them is not changed and named. (0.3.46)
   - **Settings** (beside the aspect ratio, 0.3.47) — where the resolution, Steps and CFG of every shot come from. Nothing has to be set in Generate first.
     - *This movie's settings* (default): **Resolution** offers Generate's choices (*Native* = the model's pixel count, 144p … 2160p, the MP steps; no fixed size, no custom). Each shot gets the exact canvas Generate's resolution settings compute for the aspect on H3's 32-pixel grid. The line under the row shows it, e.g. *1152×672* for 16:9 at Native, *1248×736* at 720p; with *Auto* aspect the size comes from the first reference picture at that resolution. **Steps** and **CFG** start at the default model's starting values: 30 steps and CFG 3 for the MiniMax H3 base model, and 8 steps and CFG 1 for a file named *turbo* or *lightning*. Such a file is taken as a merge of the 8-step turbo LoRA (filename evidence only; family data `variants`). The line says which values are in use; **↺ Model values** returns to them after an edit. These Steps/CFG belong to the default video model, which is saved with the movie; choosing another default model returns to its own values. A scene with its own model uses that model's starting values and can set its own Steps and CFG in its *Model and LoRAs* block (empty = the value shown). The sampler and scheduler are the model's (res_multistep / simple for H3).
     - *Generate's settings*: each shot uses the resolution, Steps, CFG and sampler that Generate shows for its model; only the aspect ratio comes from the movie.
   - **Music** (0.3.47) — the music bed for the whole film, in the same step so the planner sees it.
     - **Preset**: 12 instrumental starting points (cinematic orchestral, epic trailer, action, suspense, horror, ambient, gentle piano, acoustic folk, bright and upbeat, lo-fi, synthwave, noir jazz). They are data in `src/wizards/musicPresets.json`: each preset has a name per app language, a tempo, ACE-Step tags and a YuE2 Style line beginning with *Instrumental* and ending with *no vocals*, as the DaSiWa YuE2 instrumental writer writes them; invalid entries are skipped. Choosing a preset fills the style in the chosen music model's dialect and sets its tempo; editing the text makes it your own description.
     - **Describe the music** (the style), **Lyrics** (empty = instrumental; section tags such as `[Verse]` help), **Tempo (BPM)** (ACE-Step only, 10–300; empty keeps Generate's value) and **Lyrics language** (ACE-Step, shown with lyrics).
     - *Let the planner write lyrics* (off by default) asks the planner for a song instead of an instrumental bed.
     - **Write the music with the planner** asks the chosen language model for style, tempo and, if asked for, lyrics from the story, story bible and scene texts. It needs the same confirmation for an external server as the plan, and no media are sent. The suggestion is shown first; *Apply plan* fills only empty fields unless *Replace my own music text* is ticked.
2. **Plan** — choose the model (Prompt Forge's list and setup) and press **Suggest the plan**: the model reads the idea, your media (what each one is and its note — never the files or their names) and any scenes you already made, and proposes the scenes with their text, lengths, continuity and spoken lines, **placing each medium** into the scene it belongs to (people, places, objects, style, clips and sound as references; a picture as first/last frame only when it is the exact opening/closing frame; on MiniMax H3 a scene takes either references or frames). Before anything changes you see the **whole proposal** (0.3.47): the story bible (open), then every scene as the film would have it. Each scene shows its status (*new*, *changed*, *unchanged*, or *made — stays* when a made scene is left alone), title, length and what H3 will really make (*10 s (H3 makes 10.13 s)*), the transition, what happens, *At the start* / *At the end*, the spoken lines with delivery and the media placed in it. A changed scene has a *Before* section with its old title, length and text. Scenes that would be removed and scenes kept after the plan's are named, followed by the suggested music (style, tempo, lyrics, and whether your own text stays), warnings and the counts. Media the plan did not place are named. **Write my scenes** instead fills in your own scenes and keeps their number, lengths and inputs. The story bible the plan writes sits in a closed *Story bible* section.
3. **Scenes** — a composition view with three lanes: **Scenes** (one Library-style card per scene, as wide as the scene is long), **Music** (the music bed as one card) and **Film** (the joined film). **+** sits on the left and adds a scene after the open one (else at the end). Every scene card has its own **✕** (top left) that removes that scene (0.3.48): a scene that is not made goes at once, a made scene asks first (its clip file stays on disk), and a scene that is being made cannot be removed. If its panel was open, the panel moves to the neighbouring scene. A scene card shows its picture (the first input), its state, its name (*Scene 1* until you rename it with ✎ — a short field on the card), its length, a mark per input (⇤ first frame, ⇥ last frame, ▣ picture, ▶ clip, ♪ sound) and a flag for its own LoRAs (◆n); a made scene shows a frame of its own clip. Clicking a card opens its settings in a **panel that does not block the page** — it opens centered, moves by its title bar and resizes at the corner like the detached prompt editor (× or Escape closes it; clicking another card switches it). Made scenes, the film and the scored film play in Generate's preview player (the native player in the Linux app): for a scene its length, text (what happens and who is in it), **Inputs…** (Generate's own References overlay with the roles the scene's model can take and every Director option — see below), model and LoRAs, *Prepare in Generate* / *Make this shot* and its clip; the music card opens the music settings, the film card the join. Between two scene cards a **transition chip** chooses how the film goes into the next scene: **Seamless** (H3 continues the previous take — one continuous shot, made together with the scene before it), **Cut** (a hard cut) or **Blend 0.5/1/2 s** (picture and sound cross-fade; the film is then stitched with FFmpeg instead of the Join clips recipe; a crossfade is at most half of either clip). Changing Seamless ↔ not seamless means the scene is made again; changing between cut and blend only re-stitches the film. There is no lock switch (0.3.45): re-planning leaves made scenes alone unless you tick *Also rewrite made scenes* in the proposal.
   - **Inputs…**: pick a file in the media panel, choose how it is used in the role bar, press *Assign*. For MiniMax H3 a picture can be the first frame, last frame, both or a reference; clips and sound are references; frames and references are not mixed in one take (the role bar says why). Each reference keeps the full Director options of Generate's References editor (label, people, keep/drop, notes, trims); *Insert* puts its `<Picture 1>`-style tag into the scene text.
4. **Film and music** — **Make the movie** makes every scene that is not made yet, one after another (a seamless run as one Continuity chain), then stitches the film, then — when the plan or you set up the music — generates the music bed and mixes it in. Nothing has to be made scene by scene; **Stop after this step** stops admitting the next wizard stage while letting the active stage (including a whole Continuity chain) finish and keep its clip — a running job is not cancelled from here, and finishing the last scene after Stop does not start an automatic stitch, music generation or mix. A failed step stops the run with the reason; remake that scene on its own and press **Make the movie** again — made scenes are not made twice. Every scene stays remakeable on its own (its panel), and whenever every scene is made and the film is missing or outdated after an intentional manual remake or a changed transition, the film is **stitched again by itself** once. Active generation, stitch and mix slots stay owned until their operation settles (scene/chain and music Prepare/Make share the Generate hand-over guard, **New** and **Saved movies → open** wait until an active stage settles, and the film panel's **Stop** stays reachable for a running stitch). Pending completions stay bound to the movie draft, revisions and effective submitted inputs — including references contributed by later scenes in a Continuity chain and the H3 audio-reference track and trim offset from earlier scenes — so a stale reply never marks the current draft complete while keeping the output file on disk and existing job/revision history intact. The film and music cards keep their own settings (see *Joining the film* and *Music bed* below).

**Save movie** writes the plan to the `movies` folder under DEAS' app data (atomic write, one file per movie); **Saved movies** lists and reopens them. The movie being edited is also kept as a working draft (0.3.47): switching to another wizard or tab, or restarting the app, brings it back (*Your unsaved movie was restored*). **New** clears the draft. Reopening never starts, resumes or resubmits anything, and a damaged, oversized or newer file is reported ("N damaged movie file(s) were skipped") and left exactly as it is. Every edit keeps the earlier text as a revision, and editing a scene marks everything built from it (the film, the scored film) outdated. Beginner's **Wizards** page shows the same Movie Maker entry.

### Story plan

**Story plan** asks a language model — any model Prompt Forge has (local GGUF, Ollama, OpenAI-compatible; the list, configuration and endpoint are Prompt Forge's, read from the environment like Prompt Forge and Chat since 0.3.42; nothing you pick here becomes a default) — for a **story bible** and the scenes. Two buttons:

- **Suggest the plan** suggests the scene list from the story and places the media of step 1 into scenes. If the model leaves a medium out (smaller models often skip the optional `inputs` field), DEAS puts it into every scene without frames as a reference, within H3's counts (12 items, 9 pictures, 3 clips, 3 sounds), and says so; the proposal lists per scene which media it gets. The plan also suggests the **music** for the whole film: its style and tempo, and lyrics when *Let the planner write lyrics* is on. A style you chose is kept and the lyrics are written for it. Each part is filled only where you have nothing of your own and no track; the music's length, model and mix stay DEAS' defaults. Made scenes are left alone unless *Also rewrite made scenes* is ticked. Your scenes are paired with the suggestion in order; a scene holding your inputs, or a made scene, is never dropped, even when the suggestion has fewer scenes, and its inputs are never touched.
- **Write my scenes** (needs scenes) writes the title, text, start/end state and spoken lines of **your** scenes and keeps their number, lengths, continuity and inputs exactly.
- **What is sent:** the title, aspect, story, the media pool as *m1. picture — note* lines and, per scene, its length, continuity, text and *what kind* of inputs it has with their labels and notes (e.g. *reference picture (character-1 — Anna, red coat)*). **Files and file names are never sent.** A request above 6000 characters is refused instead of truncated (the planner's window is 4096 tokens).
- **External servers:** if the endpoint is not on this computer, a confirmation names the host, the characters and the number of scenes before anything is sent; *Cancel* sends nothing. A loopback endpoint (`localhost`, `127.x`, `::1`) and local GGUF models need no confirmation. There is no fallback from a local to a remote model.
- **The proposal:** the answer is validated strictly (segment limits and 0.5 s steps when suggesting, no continued first scene, every spoken line has a speaker; a speaker the text does not name is a warning). If it is not usable you see the reasons and nothing changes; a usable one shows what *Apply plan* would do (new / changed / unchanged / kept / removed scenes, the story text, finished items that would become outdated).
- Segment limits come from the family data (2–15 s in 0.5 s steps for H3, unverified). Nothing is rendered by this step.

### Making the shots

The selected scene's editor has **Prepare in Generate** (fills Generate with the scene's draft and switches there; nothing runs) and **Make this shot** (runs it through Generate's normal Run, queue and Stop, and stays in Movie Maker to show progress and the finished clip).

- **What is made:** a scene that starts a new take — the first scene, or any scene whose transition is not *Seamless* — as a MiniMax H3 draft with exactly its inputs: references → REF2VA (up to 12, with every Director option they carry), first/last frame → I2VA / FL2VA, no inputs → text-to-video. The prompt is the scene text plus *At the start* / *At the end* states and the spoken lines (*Anna says: "…" (delivery)*). Seconds come from the scene; canvas, Steps, CFG, sampler and scheduler come from the movie's **Settings** (step 1; with *Generate's settings* only the aspect goes over). The Run Plan shows the real frame count.
- **Result:** a finished clip is stored as the scene's result (file path and job) and plays under it; a failed or cancelled run marks it failed with the reason. Editing a scene afterwards marks it *outdated*; earlier results stay in its revision history.
- **Model:** the installed MiniMax H3 file, Turbo/int8 first; choose another when several exist (the selector is in the Scenes header).
- **Model and LoRAs per scene:** the *Model and LoRAs* block of each scene picks a different installed MiniMax H3 model for that scene than the default, and up to 8 LoRAs of that model family with a strength each (−4…4). With the movie's own settings the block also has **Steps** and **CFG** for the scene (empty = the scene's model's value, shown as the placeholder; a change makes a made scene outdated). Making or preparing the scene hands Generate exactly that model and those LoRAs (it replaces any LoRAs Generate had selected); a model or LoRA that is no longer installed blocks the scene with its name instead of being dropped. A continued scene has no block of its own: a chain is made with the first scene's model and LoRAs. The music bed has its own LoRAs (see *Music bed*).
- **Continued scenes:** a scene with a *Seamless* transition is made together with the first scene of its chain — see [Chains](#chains-continued-shots). Save the movie to keep the recorded results.

### Joining the film

The **Film** step sits under the shots. It is enabled when every shot is made, up to date and a video file; otherwise it lists each shot that is not (*not made yet*, *outdated*, *failed*, *its result is not a video file*, *continues the previous shot*).

**Join the shots into one film** copies each shot's clip into the backend's Input folder (in plan order), asks the node pack's own join check, and then runs the same **Join clips** recipe as Continuity with smooth audio seams. Shots are cuts, so the clips are concatenated, not blended. **Stop** cancels the copy or the join job. The finished film plays under the step and is recorded on the movie (save the movie to keep it). If the joined length differs from the shots' total by more than 0.25 s you get a note. Editing a scene or the story afterwards marks the film *outdated*; a refused or failed join records nothing and shows the reason. Needs the desktop app and a running backend.

### When files are missing on reopen

After **Saved movies → open**, Movie Maker checks which recorded clips (scenes and the film) and scene inputs are no longer on disk and lists them with the scene name. It only checks that each file still exists; nothing is opened or changed. **Mark the missing clips as not made** resets those shots to *not made yet* and marks the film and anything built from them outdated (earlier results stay in the history); missing inputs stay as they are until you replace or remove them. A movie opens whether or not files are missing.

### Chains (continued shots)

A chain is the first shot after a cut plus every following scene with a *Seamless* transition. On the chain's first shot the buttons read **Prepare the chain in Generate** and **Make the chain (n shots)**; continued shots say they are made together with it.

- **How it runs:** Generate uses H3 Continuity: shot 1 is a new first take (its camera/action text is the prompt), each following shot continues the clip before it with its own text as the action, with the default 22-frame overlap and *segment* output (each shot's file holds only its new footage). The references of **all** scenes in the chain are the references of every step (without repeats), so a person who only appears later is available; the first scene's frames start the take instead when the chain has no references (H3 cannot mix the two, so a chain with frames on its first scene and references on a later one is refused with the reason); without inputs the chain is text-to-video. Continued shots last in whole 17-frame steps (the *Will be made as …* line shows it).
- **Your own plan is safe:** the chain runs on its own temporary plan. Continuity shows *This chain's plan (n shots) belongs to Movie Maker*; **Back to my plan** (disabled while a step runs) returns to yours, and starting any other hand-over does the same. Your saved Continuity plan is never changed.
- **Progress and results:** each shot shows *making …* while its step runs and is recorded with its clip when it finishes; the chain stays busy until its last shot ends. A failing step marks that shot *failed*, the rest stay *not made*, and Stop in Generate stops the chain (if an in-flight intermediate shot still finishes with a valid clip while stopping, that clip is kept before the chain ends without starting the next shot). If Generate cannot start a shot of the chain or cannot resolve and pin the previous take's session clip after a finished shot, Generate reports why the chain cannot continue, releases Movie Maker's active run, stops automatic advancement and keeps any clips already completed.
- **Refused chains:** a first take over 362 frames, a continued step that leaves no room for the overlap in the 362-frame window, or a shot over 15 s is not sent; the message names the shot.
- **Rerunning:** *Make the chain again* always remakes the whole chain from its first shot (a new session take); there is no restart from a middle shot yet.
- **Film:** the join takes the chain's clips like any other (in plan order). Whether the seams of continued clips are invisible in the joined film has not been checked on real footage.

### Music bed

The **Music** step sits below the Film step and needs a music file you choose; the mix itself needs the joined film (made and up to date).

- **Choose a music file** — WAV, MP3, FLAC, OGG, Opus, M4A, AAC or WMA. The file stays where it is. Without a film joined yet the step says so.
- **Or generate the track:** set up the music in step 1 (preset, style, lyrics, tempo — see *Music* there), then **Generate the track (n s)** in the music card — a text-to-music draft (instrumental unless there are lyrics) of the film's length (the joined film's length when it is made, else the planned shots') on the installed ACE-Step 1.5 model (Turbo first; other ACE-Step variants next) or YuE2. The style goes in the music model's dialect; ACE-Step 1.5 also gets the tempo and lyrics language when set, and, with the movie's own settings, its variant's starting Steps/CFG/sampler (Turbo 8 steps CFG 1, Base/SFT 50 steps). **Prepare in Generate** only fills the draft. YuE2's weights are licensed CC-BY-NC (non-commercial) and the step says so; ACE-Step 1.5 has no such restriction in the sources checked. The finished track becomes the music file (the scored film goes outdated); a failed generation shows the reason. Both buttons are disabled while a shot, the track or the mix is being made.
- **Music LoRAs (0.3.41):** the closed *Music LoRAs* section under the music model adds up to 8 LoRAs of the chosen ACE-Step model's LoRA family (1.5 or 1.5 XL) with a strength each (−4…4). Generating or preparing the track hands Generate exactly those LoRAs — also none, so LoRAs left selected in Generate never ride the track. A LoRA that is no longer installed blocks the track with its name; YuE2 takes no LoRAs, so a YuE2 model with music LoRAs set refuses with that reason. Changing them marks the track outdated.
- **Settings:** *Music level* (−40…6 dB, default −14), *Duck under the film's sound* (0–30 dB, default 12; 0 turns ducking off) and *Fade-out at the end* (0–10 s, default 2, at most half the film).
- **What the mix does:** FFmpeg first brings the track to a fixed loudness (−24 LUFS), so *Music level* means the same for a quiet generated track and a loud mastered song; then it repeats or cuts the track to the film's length, applies the level and fade, and — when the film has its own sound, such as the speech MiniMax H3 generated — compresses the music with the film's audio as the trigger, so the music drops whenever the film itself is loud. Both are then summed without normalising, so the film's sound keeps its level. The video stream is copied unchanged; the audio is encoded as AAC (Opus for WebM). Because the music is mixed in afterwards it is exactly your track, never a re-synthesis.
- **Result:** the scored film is written beside the joined film as `<name>-scored.<ext>` (then `-scored-2`, …) — a fresh name every time, never an overwrite — plays under the step, and is recorded on the movie (save to keep it). Changing the music file, any setting, or the film marks it *outdated*; the joined film itself is never touched.
- **How the music joins the film:** *Mix it under the finished film* (default, the exact track) or *Give it to H3 as an audio reference of each shot*. In the second mode each **cut** shot is handed to Generate as REF2VA with its references **and its slice of the track** (from the shot's place in the finished film, as long as the shot) as audio reference; H3 makes its own sound guided by the music — not a copy — and no mix follows; the mix button says it is off, so the music is never doubled. Needs: a picture reference on the scene (H3's audio reference needs one), a slice of 2–15 s, a track at least as long as the shot's place in the film, and a shot that is not part of a chain of continued shots. The model and LoRAs of the shot apply as usual.
- **Speech:** external dialogue is never layered over H3's own speech; speech in the film comes from H3 for now. If you later pass the music to H3 as an audio reference instead (planned, optional), that mode and this mix are exclusive per movie, so the music is never doubled.
- **Missing file:** reopening a movie reports a music file that is no longer there.
- **Needs:** the desktop app and FFmpeg (with ffprobe) on PATH.
