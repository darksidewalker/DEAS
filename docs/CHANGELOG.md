# Changelog

## 0.2.23 BETA (unreleased)

- **Maximize button for videos.** The native Linux video player (preview, Media, references) gets a **Maximize video** control that fills the window with the same player — no reload, playback keeps running; the button or Escape restores it.
- **Face refinement default strength 0.3** (was 0.35). Previously saved values are kept.
- **Inpaint: Context padding next to *Inpaint only masked*.** The crop margin for masked-only inpaint was only reachable inside the SAM group of the Post-Processing dock and was mislabelled *Mask Shrink Grow* (it never grew the mask). It is now **Context padding (px)** directly below the checkbox in the settings (greyed while off), still shared with the SAM refine margin; the blur keeps being added so soft edges stay inside the crop. Saved values unchanged.
- **De-rope: distilled generation is an explicit choice.** The *Generation model* pass no longer guesses distillation from the step count (≤ 8 steps silently switched a base model to the 6-step turbo schedule, and a distilled model above 8 steps got 25 steps). A new default-OFF **Generation is distilled (turbo)** switch runs the turbo schedule on the generation chain as-is, its turbo LoRA included; otherwise 25 steps. Saved intents without the flag now run the 25-step pass.
- **De-rope: Keep static background.** New default-OFF H3 De-rope switch uses the existing baseline frames to retain static detail around motion/structural changes, with spatial/temporal mask stabilization and conservative broad-motion fallback. Requires the additive Recover ABI in DaSiWa nodes 0.5.45; old packs keep ordinary De-rope usable, while saved background preservation blocks Run until compatible. Original/audio and OFF graphs stay unchanged; no new model/dependency. Same-clip CPU A/B shows partial detail recovery, not universal baseline-sharpness or flicker-free acceptance.
- **Original before learned video latent upscale.** H3 and LTX now save the unprocessed video before any learned latent-upscale work, even with no other post-processing enabled. H3 Continuity New segment only retains the exact pre-upscale segment audio and keeps its single required Segment Decode; processed video decoding/cropping runs behind the existing lazy gate. Missing/incompatible gate or saver capabilities block Run rather than falling back to unsafe ordering. CPU executor and graph checks cover retention after downstream failure/interruption; real-model and native-platform acceptance remain separate.
- **H3 de-rope for fast motion.** H3 Post-Processing gains **De-rope (fast motion)**, off by default: after the Original is saved, hot motion spans are slowed, re-rendered at partial denoise with a selectable turbo LoRA (6 steps) or the base model (25 steps), and sped back up by exact frame selection, keeping the baseline audio; first/last-frame keyframes are moved onto the slowed clock so the recovered last frame stays pinned. Oracle preset and inject fraction (0.48/0.70) are selectable. Ported from MATLOWAI's MAINodes Motion Lab into the DaSiWa node pack (0.5.43) as two nodes; H3 only for now (LTX/Wan tracked in the plan).
- **Face refinement always runs at least 2 steps.** On short (distilled) schedules the strength used to round down to 1 step — or to none below 0.125 on a 4-step generation, silently skipping the refine; refine now gets its own schedule with at least 2 executed steps, the strength is unchanged.
- **Moving face crops.** A face that walks across the frame is refined in a face-sized crop that follows it instead of one large static crop with less detail.
- **Face refinement minimum face size.** A new *Minimum face size (px)* control (default 0 = refine every face) skips faces that never reach the given height; each skip is logged.
- **De-rope with distilled generations.** The *Generation model* pass now uses Motion Lab's 6-step schedule when the generation itself runs ≤ 8 steps, and a picked turbo LoRA the generation already carries is not stacked twice.
- **De-rope and face refinement before latent upscale.** Both now combine with H3 latent upscale: they fix the base-resolution clip, the refined frames are re-encoded beside the original audio latent and the upscaler refines that result. The saver's audio also passes the baseline gate, so the Original is always encoded before the upscale runs. Both also work with Continuity: Full timeline processes the whole decoded timeline; New segment only processes the decoded render window (source tail + new segment) and cuts back to the segment. De-rope is unavailable only for a new segment continued from an imported video.
- **H3 face refinement.** H3 Post-Processing → face analysis gains **Refine faces**: SAM3.1 tracks faces in the selected window of a 24 fps video, each tracked face is re-sampled by the current MiniMax H3 model in a square 768 crop (strength = share of the H3 schedule, default 0.35; crop context 2.5× face height; 6 px edge feather) and stitched back with the original soundtrack held, so lips stay bound to it. **Refine faces after H3 generation** (default OFF) adds the same stage to every H3 run. Both keep the unrefined Original (saved first) and the refined Processed video. Detect hard cuts restarts tracking per shot. Runs on the owned backend through the bundled DEAS adapter and core SAM3/H3 nodes only; no extra installs. Not available together with H3 latent upscale yet; non-24 fps sources are refused, not resampled.
- **Join clips in Continuity.** The Continuity overlay can assemble a session's saved segments (**Select chain to here**) or chosen video files (trims, order, optional lossless copy) into one video without loading a model; the node pack's preflight shows mode and duration before **Join now**, and the result appears in the normal queue/Media. H3 transitions per cut are not offered yet.
- **SAM video window keeps sound when asked.** The bundled window adapter decodes the source soundtrack for refinement (mask analysis stays silent); audio packets no longer go through the video-geometry check.

- **Optional cut-safe SAM video analysis (HF2a).** Detect hard cuts defaults OFF. When enabled, a bounded RGB-frame-difference heuristic resets SAM tracking at each detected boundary within the selected analysis window; source frame order, dimensions, count and cadence stay unchanged. The threshold starts at an uncalibrated 0.3, and shot ranges reach central Logs. Missing/incompatible cut adapters block only this option; OFF preserves the original analysis payload/graph. No new detector/runtime, automatic generation or face-refinement claim.

- **H3 face-mask video analysis (first stage, not Face Refine).** H3 Post-Processing can explicitly analyze a selected local video window with installed SAM3.1 and retain a silent union-mask video in the normal queue/preview. Checkpoint, confidence, time window, maximum faces and detection interval are editable; opening/editing does not execute. The native recipe uses core SAM video tracking plus a bundled pre-decode window/memory guard, with existing job ownership/Stop and no third-party nodepack installation. Diagnostic masks stay outside restorable generation history. Scene-aware crops, H3 refinement/stitching and automatic chaining are not yet implemented.

- **Compact Inpaint SAM controls.** SAM settings now live only in Post-Processing, reached through the normal Post-Processing dock tab, without an extra button in Inpaint settings. The verbose target/refinement and manual-install help paragraphs are no longer shown in the controls; licensing and manual installation remain documented. Add target mask opens Post-Processing: empty targets focus and briefly highlight the SAM targets field without execution; supplied keywords create masks. The automatic-refine checkbox is on the left and the manual Auto Refine button on the right.
- **SAM checkpoint auto-selection.** An available SAM checkpoint is selected when the current choice is empty or unavailable; a valid saved choice stays selected. Explicit Models → Reload refreshes the backend choices too, so newly added weights become selectable. No model is downloaded and no processing starts from selection.
- **SAM point picking keeps the editor image.** Segmentation adds a mask to the current source without jumping to the latest queue image or starting generation/Auto Refine.
- **Queue stars on the left.** Result-row star buttons now match the Media panel placement.
- **Cleaner preview toolbar.** Open in Media Analysis and Export without metadata… are in More instead of separate preview buttons; their media context-menu actions remain available.

## 0.2.22 BETA

- **Seamless loop for videos.** LTX, Wan and MiniMax H3 Post-Processing (and the TVE tab) gain a **Seamless loop** stage, off by default. It runs first in the post chain with the DaSiWa Seamless Loop node (RIFE/FILM `.safetensors` model or RTX Frame Generation), turns the clip into a loop by trimming and morphing its end into its start, and cuts the generated audio with exactly the same frame mapping, so picture and sound stay in sync. **Loop audio → Beat-aware** additionally picks a loop length of whole beats when the music has a clear tempo, so the beats line up across the wrap; without a clear tempo it falls back to the plain crossfade. The loop shortens the video; the Original stays saved. Needs DaSiWa nodes 0.5.41 (Backend → Upgrade → ComfyUI and node packs) and a backend restart.
- **Video post-processing saves the Original first.** With TVE stages enabled in a video pipeline, the unprocessed video is now encoded before any post-processing node (including its upscale/interpolation model loaders) starts, so a failing or stopped post chain can no longer cost you the Original. Works for LTX, Wan and MiniMax H3; videos without post-processing get exactly the same graph as before. Restart the owned backend once to load the updated DEAS adapter; until then such jobs are refused with a reason. The learned latent upscale is not covered yet.
- **Time left next to the step count.** While a job samples, the preview, the working note and its queue row show an estimate such as `12/30 · ~45 s left`, measured from this job's own step pace after two steps. A new pass (refine, second video pass, SAM pass) starts a fresh estimate.
- **Arrow keys in the full-window viewer.** Left/Right (or the new ‹ › buttons) step through the finished picture results of the queue, Original and Processed included, with a position counter; the viewer stays open, so an inpaint result can be compared directly with earlier ones. Videos are skipped.
- **Export without metadata…** in the Media right-click menu, the preview toolbar's **More** menu and a finished queue row's right-click menu saves a copy without prompt, workflow and settings to a place you choose. Pictures (PNG/JPEG/WebP) keep their pixels and colour profile byte for byte; videos and audio are remuxed without re-encoding. The original file stays untouched, and an existing file is never overwritten.
- **Comfy tab hand-offs work again with newer ComfyUI frontends.** ComfyUI frontend 1.57 no longer exports `app` from its `/scripts/app.js` shim, so every hand-off into the Comfy tab (Media's metadata pane, Open in ComfyUI) timed out; the bridge now uses the live `window.app` and falls back to the old import.
- **Media Analysis tab (ported from PromptForge).** Studio → Media Analysis reads a picture's booru tags with ONNX image taggers on the CPU (a private hash-locked runtime, `src-tauri/src/analysis.rs`), shows its embedded generation settings, and can open its ComfyUI workflow in the Comfy tab through the existing editor hand-off. Taggers are discovered where people keep them (`models/taggers`, `models/onnx`, `models/animetimm`, tagger-named model folders, tagger nodes in `custom_nodes`, Hugging Face cache layouts) and read with their own tag lists in WD/animetimm CSV, other CSV, JSON (index maps, PixAI `tag_map`, Camie `idx_to_tag`) or text form; uncategorised lists are classified with the bundled Danbooru table. Unusable finds (PyTorch-only, no tag list, unreadable list) are listed with the reason. Setup with a found tagger installs only the runtime; the WD v3 EVA02 download is offered only when nothing is found. **Describe** sends the picture and its tags to the configured vision LLM with PromptForge's `describe.md` and the recognised series' cast (newly bundled `character_series.json`), returning Description, Characters and a Tagger check whose suggested tags are verified against the tag table. Videos open in a **frame picker** with frame-exact FFmpeg extraction by frame number: step, pick, save PNGs, use a frame for tags/Describe, or send it to Generate as a Wan/H3 first/last frame or H3 reference (picked frames go as references in one click). animetimm checkpoints kept as PyTorch weights (ComfyUI's animetimm node) can be **converted to ONNX** once, on request, with PromptForge's exporter in a throwaway hash-locked PyTorch-CPU environment whose downloads are kept while other checkpoints wait and removed after the last one (`src-tauri/src/analysis_convert.rs`); the copy is checked against PyTorch and listed as a tagger. Describe gets PromptForge's **Temperature** and **Repeat penalty** sliders (presence penalty, a new optional field on Forge's chat round, unset everywhere else), and its model list now loads when a picture opens (when an LLM is set up), so Describe never runs on a model nobody picked. **Made with** now reads ComfyUI pictures like PromptForge (checkpoint, LoRAs, seed through seed nodes, sampler, steps/CFG/denoise, the typed part of wildcard-built prompts; `src/lib/comfyMeta.ts`) with Copy and Send to Generate, instead of a raw list of node fields. The frame picker plays and pauses the clip (pausing lands on an exact frame), a used frame can go back to its video with the picks kept, and the stage keeps its size while a frame is clicked or still loading. [Media Analysis](MEDIA-ANALYSIS.md).
- **Create RefMods in the References tab.** MiniMax H3 references can now be saved as a reusable RefMod file without the Comfy tab: **Create RefMod…** beside the RefMod library opens the Director's create form (tick references, per-reference descriptions, name, concept, description). It runs as one separate backend job, can be cancelled, never overwrites an existing file and selects the new RefMod in the library when done. References and prompt stay unchanged.
- **RefMods in your models folder are found.** With a custom models folder, the DEAS-owned backend only looked in its own `ComfyUI/models/refmods`, so RefMods in `<models>/refmods` (shared with other ComfyUI installs) were missing from the library. The backend now registers `<models>/refmods`; new RefMods are saved there. Restart the backend once to pick it up. RefMods with more than 16 entries are no longer hidden from the library.
- **Stop asks only when there is more than one thing to stop.** With a single run, **Stop** now stops it straight away instead of opening a menu. The menu with choices appears only when more work is queued, and its first item is now **Stop current run** (it stops the run that is generating, not whatever queue row happens to be selected).
- **Switching pipelines keeps the prompt when the output stays the same kind.** Text → Image ↔ Image → Image, the video pipelines among each other, and Text → Music ↔ Cover now keep the prompt (and negative prompt or music texts) on screen instead of bringing back the one last typed in the other pipeline. Switching to another kind (picture → video → music) still restores that pipeline's own prompt. Settings, references and input media are remembered per pipeline as before.
- **Chat can use local GGUF models.** Chat's model menu now lists the same local GGUFs as Prompt Forge and runs them through the same local runner, with the same tools (tags, guides, prompt writing, drawing). A server stays the default when one is set. The local model answers each round in one piece and is unloaded when the turn ends, so a requested picture gets the whole GPU.
- **SAM Auto Refine shows its passes in the queue.** While Auto Refine masks and refines, each SAM and refine pass now appears in the queue with its live state. Before, the queue stopped updating once the base picture finished, so nothing moved until the whole chain ended or was stopped. The passes were already running as normal queue jobs; the queue just stopped checking for them.
- **Videos show a picture instead of ▶.** Media tiles (all views) and finished video rows in the queue now show the video's first frame, taken once with FFmpeg and cached, with a small ▶ badge so videos stay recognisable. If FFmpeg cannot read a file, the ▶ tile stays. No video player is opened per tile.
- **Dock tabs count what is switched on.** Wildcards, Post-Processing and Options show a small number badge with how many settings are active or changed from default (LoRAs already showed its count); no badge means everything is at default. Options no longer counts settings that are stored but unchanged, and Post-Processing now also counts SAM Auto Refine, TVE stages and audio enhancement.
- **Slider no longer shows "?" for videos.** The Slider compare only works for pictures; on a video result it is now greyed out with the reason instead of opening a broken view.
- **Paste pictures into Media and References.** The Media header has a new **Paste or drop here** field: click into it and press Ctrl+V to save a clipboard picture (a screenshot, a picture copied in the browser) into the Input folder, or drag a picture/video from the Media tiles or the file manager onto it to copy it there. The new file is selected right away, nothing is overwritten and the original stays where it is. Ctrl+V inside the open References tab adds a pasted picture as a reference the same way.
- **Beginner shows Steps and CFG.** The Beginner composer now has the same Steps and CFG fields as Advanced (same limits; fixed-schedule models stay locked with their reason), so a Turbo or speed-LoRA setup no longer needs a trip to Advanced. Switching between Beginner and Advanced keeps the values; only picking another model resets them to that family's starting values.
- **Prompt text in the Comfy tab is sharp at every zoom level.** WebKitGTK painted ComfyUI's text boxes (prompt nodes) at 1× and stretched the image with the canvas zoom, so they got blurrier the further you zoomed in while the rest of the graph stayed crisp. The Comfy tab now scales those boxes with CSS zoom instead, so the text is drawn at its real size; position and size match exactly as before.
- **Stop opens a small dropdown instead of a full popup.** Clicking **Stop** now drops a compact menu right above the button with **Stop selected item** and **Stop all**. Escape or a click outside closes it. If the selected item can't be stopped, the reason appears right under that entry.
- **Optional audio engine installs show live progress in Logs.** Installing Stems or Deep (and running audio enhancement) used to sit on "Running the inference check… may take several minutes" with nothing in Logs, because the runtime's CLI output was only read back after a failure. Each install stage is now logged as it starts, and uv/pip/inference output streams into Logs line by line (tokens, URLs and private paths are still redacted).
- **Stems GPU binding no longer picks a random Python.** The optional CUDA codec bridge was installed with whatever interpreter uv found first (e.g. a miniconda CPython 3.13), so the cp312 wheel was rejected and Stems fell back to CPU-only with an error in Logs. It now resolves for the owned ComfyUI environment's Python, the one that loads it.
- **Stems installed CPU-only can add GPU support afterwards.** When Stems is installed without the GPU binding and an owned ComfyUI environment exists (Linux), its engine button turns into **Reinstall Stems — vocals + instrumental with GPU…**. It asks for consent, then only adds the small isolated codec package and runs one CUDA check; the verified CPU runtime and the ComfyUI environment stay untouched. If the GPU check fails, Stems stays CPU-only and Logs names the reason. Once the GPU binding works, the button is disabled again.
- **Prompt Forge writes for Qwen Image 2.1 (and Turbo).** The hammer, the Prompt Forge tab and Chat now have a native Qwen Image 2.1 writer instead of "no prompt style for this model". Its guide is written for DEAS from Qwen's official prompt-rewriting instructions (QwenLM/Qwen-Image-2.1 `prompt_rewrite`): one long English observer-style paragraph (about 400–500 words) in the model's trained order — opening line, background, a walk through the frame, a sentence about the light, one closing sentence about the composition — with in-picture text in straight double quotes, no quality boosters, no aspect ratio written into the prompt and no negative prompt (the model has none). Detail, Creativity and lighting controls are the same as Krea2's; Styles use MOSS's descriptor set and are handed to the writer, not pasted after the closing sentence. The guide ships as a DEAS-owned `forge-data/deas-models.json` layered over the upstream PromptForge pack, so pack updates do not remove it. The same writer is proposed upstream under the same key (`qwen_image`), and the upstream one takes precedence once the pack carries it.

## 0.2.21 BETA

- **Comparing models in the same family keeps your settings.** Switching between checkpoints of one family (e.g. two H3 models) reset Steps/CFG/sampler/scheduler/size back to the family defaults every time, so A/B comparing variants meant re-entering settings. Now the settings on screen carry over to the first visit of a same-family checkpoint (its own remembered draft still wins when it exists, and changing to a different family or pipeline still applies that family's defaults).

- **Consent popups now sit on top of the video preview.** The native video preview composites on its own surface above the app page, so the browser's built-in confirm boxes rendered blended *behind* the preview — the "install missing engine" consent (e.g. the audio stem model) was half unreadable. Every confirm (audio engine install consent, restoring job settings over editor edits, Studio defaults reset, preset overwrite) now uses a real in-app dialog: the preview steps aside while it is open, it is localized in all six languages, and it is keyboard-driven (focus starts on Confirm, Escape cancels).

- **MiniMax H3 now auto-picks the clean video VAE.** With the VAE left untouched, DEAS auto-selected the alphabetically first installed H3 video VAE — so once `minimax_h3_sol_vae_*` (the fast window decoder, which can only decode through local attention windows and shows 128/256-pixel seam lines in every frame) was installed, it silently became the default and generated videos showed straight seams the same model never showed in the reference workflow. Auto-selection now follows the order the model family declares, so the proven blending `minimax_h3_video_vae_*` is chosen and the Sol decoder stays offered in the VAE picker. A VAE you picked by hand is still remembered until you change it.

- **Enhanced video preview plays as a video again.** The KJ preview companion encodes its 120-frame/8-FPS animated previews as fragmented MP4 when a video encoder (NVENC or x264) is available; DEAS's preview guard only accepted plain MP4 and rejected every such clip silently, so the enhanced preview stayed at the still-image fallback. The guard now accepts the companion's fragmented MP4 layout (still bounded to the same H.264-only, dimensions and byte-budget checks) and the preview feeds the existing looping video player, like the KJ node in ComfyUI. Previews with an audio track or other codecs stay rejected and fall back to the still preview.

- **AMD Radeon (Linux) can now run DEAS's owned ComfyUI backend.** Setup notices an AMD Radeon RX 6000/7000/9000 (RDNA2–RDNA4) card the same way it notices an NVIDIA one and recommends the AMD backend; the owned environment then installs the ROCm PyTorch build pinned for that exact card family from AMD's wheel index — the same pins the reference ComfyUI installer has proven on AMD hardware — verifies the GPU with a real computation instead of just a listing, and starts ComfyUI against it. ComfyUI itself, models, GGUF inference (on CPU), learned-model video upscaling, RIFE frame interpolation and the other stages work as usual. Two things stay NVIDIA-only, because NVIDIA's RTX SDK physically is NVIDIA-only: the RTX Video refine pass (denoise/deblur/VSR) and RTX frame generation. On an AMD or CPU backend these are now refused at submit with a named reason ("requires an owned backend installed on an NVIDIA GPU") instead of dying mid-job after the queue — model upscaling and RIFE remain offered. Intel and Windows AMD stay closed, and this AMD path is declared, not yet verified support: development happened without an AMD card, so the first real RDNA card is the acceptance gate. Caveats and later fix points are itemized in the plan (§4.8). [Backend](BACKEND.md).

## 0.2.20 BETA

- **Local vision GGUF models can now see reference pictures (#28).** A GGUF placed in DEAS's own LLM model folder runs on DEAS's built-in runner, which until now could not read pictures at all: Prompt Forge wrote from the brief alone and said so. The built-in runner now finds the vision projector that belongs to a model — a `*.mmproj*.gguf` sitting next to the model file with a matching name (`<name>.mmproj-Q8_0.gguf`, `mmproj-<name>-f16.gguf`, or a lone `mmproj-*.gguf` in that folder) — loads it, and Prompt Forge sends reference pictures through the read and write rounds like with any server model. A model without a projector keeps the honest old behavior: the pictures are not sent and the write says why. A picker entry shaped like a folder path (`GGUF/…/model.gguf`) is DEAS's local copy; the entry named by your configured server is the server's copy, where the server's own vision handling applies.

- **Prompt Forge stops runaway writers.** A write with Length on Default had no ceiling at all, so a small model stuck repeating itself ran until it filled its context (an 8B wrote 131,772 characters over six minutes) and the cut-off text was then kept as the prompt. Every write now has an 8,192-token ceiling unless you set a Length, and a write that reaches it is refused ("the writer did not stop… try again, or pick a bigger model") instead of kept. Real prompts, MOSS Detail 10 included, stay far below it. A Length you set still cuts off exactly as before. Applies to the Prompt Forge tab, the hammer, revisions and Chat. [Usage](PROMPTING.md#prompt-forge).

- **Chat makes pictures and writes prompts itself.** Ported from PromptForge's chat: a new `render_picture` tool writes the prompt with the Prompt Forge writer of the checkpoint selected in Studio → Generate and draws it there, with Generate's own sampler, steps, seed mode, LoRAs and options, in Generate's queue (progress, sampler preview and Stop in the chat). Chat's prompt and an optional asked size (`16:9`, `1080p`, `1920x1080`, snapped to the model grid) go into that one job; Generate's own fields are untouched. The picture shows under its prompt with size, checkpoint, seed and time, is saved like any Generate output, and the conversation records it so a change ("make the highlights teal") is written as the whole picture again with that change, and "render that again" (`same_prompt`) redraws it unchanged; as in PromptForge, earlier tool answers go back to the model as the tool call and its result rather than as text it could copy. A later picture that names no size keeps the last size asked for. **Draw again** redraws a prompt with the current settings. When Generate cannot draw (backend stopped, no checkpoint, not text-to-image, missing nodes), the tool is not offered and Chat says what to change. `write_prompt` now writes image prompts in the chat with the same engine as the Prompt Forge tab (native writer for Illustrious/Anima/Krea2/MOSS, the node pack's writer for the other image families) instead of pointing to the tab; video models still point to their Forge mode. One GPU for both: before drawing, a chat model on this PC's GPU is unloaded through its server (Ollama `keep_alive: 0`, llama-swap unload) and loads again with the next message; with Ollama an idle ComfyUI frees its checkpoint first when the chat model would not fit. A server whose unload frees no memory here is treated as remote and left alone. Right-click a conversation for Rename, Pin to top / Unpin and Delete, as in PromptForge; pinned conversations stay at the top. Six languages. Not yet in Chat: picture editing, video, more than one picture per answer. [Usage](CHAT.md#making-pictures).

- **Enhanced preview prerequisites are provisioned.** New setup and explicitly confirmed ComfyUI/node-pack updates install the pinned official KJNodes preview companion with the existing Torch constraints; app-only/Torch-only updates and opening older environments do not silently install it. Configured model roots now expose `vae_approx` and existing tiny weights under `vae` without moving/copying files. Options identifies a missing `ModelPreviewOverrideKJ` and the required update instead of blaming decoder compatibility generically. Existing saved OFF and missing/incompatible-model safeguards remain; no model weights are downloaded.

- **Video metadata is valid and readable.** DEAS saves now sanitize the embedded execution graph before publication: node-level `is_changed` cache attributes are stripped and non-finite values are rejected instead of writing non-standard `NaN` that strict JSON parsers (including Civitai's) refuse. The Studio metadata pane parses legacy files with bare `NaN` and shows the full authored prompt plus extracted settings instead of dumping the raw graph; the graph stays available in collapsed diagnostics. Uploading H3 videos to Civitai still shows no prompt until upstream Civitai recognizes the H3 node types — verified against their published parser; this is not fixable from DEAS alone.

- **Enhanced audio products keep their name and provenance.** Automatic audio enhancement now saves `…-audio-enhanced.mp4` next to the source-derived name instead of an opaque `deas-audio-UUID`, with readable collision counters; History shows the final filename. The FFmpeg remux maps global and stream generation tags (`prompt`, `workflow`, track language) from the source, including MP4/MOV `use_metadata_tags`, so Civitai-visible metadata survives the audio stage. Existing files are never renamed.

- **Video preview stays visible with Metadata open.** The native Linux video surface no longer disappears behind the Metadata panel: the preview area shrinks to reserve space beside it and the player keeps its transport state (verified against real libmpv frames in the isolated fixture). Each More menu is now owned independently, so opening/closing one toolbar menu cannot dismiss or steal a sibling's; Escape closes and returns focus. The same reservation now applies while a **More** menu is open over a native video: the preview shifts down for the menu's own area instead of the menu opening behind the video pixels.

- **"Use these settings" re-picks H3 reference media.** A MiniMax H3 REF2VA job that used video/audio/image references now restores its draft with every reference file listed by name as a missing input to re-pick, instead of blocking Run permanently with `h3.media`; lane order and trims carry over. Continuity and Ref Mods remain disclosed as not restorable.

- **FLAC/audio references play in the editor.** Local audio references use the existing native player on Linux (real duration, play/pause, crop), fixing "Source: unknown s / load error" for valid FLAC files; browser/Windows fallbacks are unchanged.

- **"Use these settings" works for finished videos.** When a shown video is no longer in the session job list, More → Use settings restores from saved job History via exact output-path match plus native availability check, instead of failing on file-embedded metadata only. Stale answers never overwrite an edited draft.

- **Theme editing stays inside DEAS.** **Quick Settings → Edit themes** now opens the bundled offline editor in its own window frame instead of handing a local `file://` page to your default browser. The editor's **Edit theme** list shows the theme folders of the selected environment and reads/saves that one folder through DEAS: only `theme.json`, an image under `assets/` or a backup under `backups/` inside one named theme folder are reachable, manifests and images are re-validated before an atomic replace, and the theme list reloads after each save. The Quick Settings hint line about the starter folder is gone (the environment hint stays when no environment is selected). The same HTML still works standalone in Chrome/Edge. Framed rendering in the shipped WebKitGTK/WebView2 window is still an open native gate.

- **Audio engine installs report what they are doing.** The install status line now names each real stage in your language (download with byte progress → Python environment → package install → inference check → optional GPU setup) and says "may take several minutes" during stages without a byte total instead of a dead-looking `0 / — bytes`. The pinned DeepFilterNet version check no longer parks an async worker. Actual native WebKitGTK/WebView2 reproduction of the reported freeze remains open.

## 0.2.6 BETA

- **Windows: the owned backend starts again (issue #11).** Symptoms in 0.2.5: Backend stayed on "Starting — verifying owned API" for 120 s and then failed with `Backend readiness timed out: Owned listener not ready` (`Owned child exited: exit code: 1`); the **Backend API** check never passed, so setup looked stuck there; Logs repeated `WARN: backend operation=GET endpoint=object_info code=BACKEND_UNAVAILABLE: error sending request`; the ComfyUI log stopped at `Set cuda device to: 0`; the "Optimizations off" startup preset made no difference, while ComfyUI started fine by hand.
